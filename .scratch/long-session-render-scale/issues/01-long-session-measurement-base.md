# 01 — 长会话度量基座：可复现的读数与真实引擎探针

**What to build:**

让"长会话性能"从靠手感判断变成可复现、可断言的东西。这是本轮的**第一交付物**——此前四轮流式性能修复的共同缺口就是没有端到端实测，各修复的相对权重至今未校准，只能靠人肉看浮层读数，下一次改动无法回答"到底哪一项起作用了"。本工单交付三件互相支撑的东西：

1. **一条合成的长 Session 夹具**：数百轮、上千条 CodeMUX Event，含 Markdown、代码围栏与较大的工具结果——规模与形状贴近真实长会话，而不是几十条事件的玩具夹具。
2. **固定种子的突流重放**：同一夹具 + 同一种子能一键重放同一段流式到达节奏（含突发与空闲），使改动前后可比。仓库里已有种子化突流源，但它目前没有被任何入口接线，本工单把它接上。
3. **一组计数型读数**：挂载与 rewind 的 store 发布代与组件 commit 数、流式期可见更新间隔分位与推进帧占比、入站帧速率、长任务累计。读数是给"下一项该改什么"用的判据，不是装饰。

以及一个**真实引擎探针**：在真实 Chromium（无头）+ 应用真实样式表下读取几何并断言布局类事实。它存在的唯一理由：现有契约测试自己在注释里承认 jsdom 不实现相关 CSS，只能断言属性有无，而本轮的若干断言（跳转落点是否精确、离屏行是否参与布局）**原理上**只能由布局引擎回答。

探针的第一条断言直接决定下一张工单是"修回归"还是"撤销回归"：**在启用离屏跳过渲染时，点导航跳到较早的 User Message，落点是否与不启用时一致且精确**。当前这只是基于机制的推论（被跳过元素自身被测量时返回基于占位高度的位置），本工单把它变成事实或推翻它。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 同一夹具 + 同一种子重放两次，读数一致（确定性，不依赖真实时钟）
- [ ] 读数以计数与比值表达；毫秒只作观测量，不作为门禁
- [ ] 真实引擎探针可运行并给出可解析的结论；当构建产物落后于源码时（例如样式表已改而产物未重建）**明确失败**，而不是静默通过
- [ ] 探针的第一条断言给出明确结论：跳过离屏渲染是否使跳转落点偏离；若是，给出偏差量级
- [ ] 长会话夹具规模与真实长会话同量级（数百轮），且可在单次测试中超时预算内跑完
- [ ] 短会话（低于长会话阈值）不进入任何新增度量路径，行为与现状一致
- [ ] 上述读数的采集入口可被后续工单直接复用，无需再改夹具或探针基座
