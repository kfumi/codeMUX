# 02 — 导航在有界渲染下仍然精确，且不再每帧读全量布局

**What to build:**

左侧回合导航在长会话里既是"位置指示器"又是"跳转入口"，它当前有两个与长会话长度绑定的问题，且必须一次解决——因为它们的失效模式是同一个：**它靠测量布局来决定行为，而布局现在可能被跳过**。

- **正确性**：依赖几何的读取（滚动时判断当前在看哪一回合、点击标记时的跳转落点、锚定修正）不再在"离屏行不参与布局"的状态下直接测量。改为在一个**显式的测量事务**内进行：进入时让相关行参与真实布局，测量与滚动完成后退出。目标是把"看起来合法的错误位置"变成"确定正确的真实位置"——长会话首次打开时早期行从未被渲染过，误差最大。
- **成本**：滚动时判断当前回合不再每帧遍历全部 User Message 逐条读取几何，改为**在布局变化时重算一次偏移、滚动期间只比较**。偏移在窗口增长、容器尺寸变化、行高变化后失效并重算。

同时把不变量钉死：**每帧执行的热循环内禁止读取布局几何**。本仓库已有"用源码契约断言约束热路径写法"的先例，沿用同一手法，使这条不变量不会在后续改动里被悄悄破坏。

跳转落点是否真的恢复精确，由 01 的真实引擎探针负责裁决——这是它存在的第一个用例。若探针结论是"未启用跳过渲染时落点本来也不精确"，那么要修的是跳转算法本身，也属本工单。

**Blocked by:** 01（需要它的真实引擎探针来验证落点精度，以及它的长会话基准来确认每帧成本确实下降）

**Status:** ready-for-agent

- [ ] 启用与不启用离屏跳过渲染两种状态下，点同一个导航标记的落点一致且精确（由真实引擎探针断言，而非 jsdom）
- [ ] 长会话首次打开、早期行从未渲染过的场景下，滚动时的高亮位置与实际视口一致
- [ ] 滚动期间不重算偏移；窗口增长、容器尺寸变化、行高变化后偏移被重算
- [ ] 存在一条源码契约断言覆盖"热循环内禁止读取布局几何"；临时还原实现后该断言确实失败（反向验证过）
- [ ] 短会话行为与现状一致；不引入新的运行时依赖
- [ ] 若探针推翻了"跳过离屏渲染导致落点偏离"的推论，需把该结论写入文档并说明本工单实际改了什么
