# 03 — UI 入口:历史用户消息 hover 回退 + 回填输入框

**What to build:** 用户可见的完整功能:hover 任意一条历史用户消息时显示撤销图标按钮(带工具提示与警告文案),点击后该消息及其后的全部内容从界面与 provider 原生历史同步消失;被回退的文本仅在输入框为空时填回,供编辑后手动重发。最新一条用户消息保留现有"编辑并重发"交互。三种 agent kind 行为一致。

**Blocked by:** 01 — Store 泛化:任意历史用户消息回退动作;02 — OpenCode 后端:按目标消息截断。

**Status:** ready-for-agent

- [ ] 历史用户消息 hover 显示撤销入口;工具提示与菜单顶部警告文案为中文("此消息之后的内容将被移除"语义),文案遵循仓库动态字号与共享 Tooltip 规范
- [ ] 点击触发 store 的任意回退动作;期间按钮进入 pending 态防止重复提交
- [ ] 回退成功后界面移除目标消息及其后全部内容;Claude、Codex、OpenCode 三种会话验证一致
- [ ] 输入框为空时填入被回退文本;已有草稿时不覆盖(only-if-empty)
- [ ] 最新一条用户消息维持现有编辑重发(onEdit)交互不变
- [ ] 无强定位标识的消息、会话运行中、只读会话三种情况下入口禁用
- [ ] 组件层挂载测试覆盖:入口出现条件、点击调用参数、回填行为、禁用态(参照现有回退用例的同一测试挂载方式);现有组件回退用例全部保持绿色
