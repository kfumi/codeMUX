# codeMUX 设计文档

## 项目概述

**项目名称：** codeMUX（AI编码工具聚合平台）

**项目类型：** 个人开发者工具

**核心目标：** 集成Claude Code、Codex等主流AI编码工具，提供统一的可视化对话界面，支持国产大模型接入。

## 技术栈

- **桌面框架：** Tauri 2（最新稳定版，支持更好的插件系统和跨平台能力）
- **前端框架：** React + TypeScript
- **数据存储：** SQLite（对话历史）+ JSON（配置文件）
- **UI风格：** 默认浅色主题，支持深色/浅色/跟随系统三种模式

## 架构设计

### 整体架构

```
┌─────────────────────────────────────────────────┐
│                  前端层 (React)                   │
│   对话界面 │ 会话管理 │ 配置界面 │ 工具可视化     │
├─────────────────────────────────────────────────┤
│               Tauri 2 桥接层 (IPC)                 │
├─────────────────────────────────────────────────┤
│                  后端层 (Rust)                    │
│   CLI管理器 │ 供应商适配器 │ 数据库 │ 文件操作    │
├─────────────────────────────────────────────────┤
│                    数据层                         │
│         SQLite数据库 │ 配置文件 │ 缓存           │
└─────────────────────────────────────────────────┘
```

### 模块划分

1. **CLI集成模块** - 管理Claude Code和Codex的API调用
2. **供应商配置模块** - 管理不同AI供应商的配置
3. **对话界面模块** - 提供可视化对话交互
4. **数据存储模块** - 管理会话历史和配置数据

## 核心功能

### 1. CLI集成模块

**集成方式：** API/SDK模式

**支持的CLI工具：**
- Claude Code（通过Claude API）
- Codex（通过OpenAI API）

**设计要点：**
- 适配器模式：每个CLI工具有独立的适配器
- 统一接口：CLIManager提供统一的调用方式
- 异步处理：所有CLI调用都是异步的，支持流式响应
- 错误处理：统一的错误处理和重试机制

### 2. 供应商配置模块

**配置方式：** 图形化配置界面

**支持的供应商：**
- DeepSeek（优先支持）
- 所有兼容OpenAI API格式的供应商
- Claude API
- Codex API

**配置项：**
- 供应商名称（自定义显示名称）
- API类型（DeepSeek / OpenAI兼容 / Claude / Codex）
- API Key（加密存储）
- 端点URL（API地址）
- 默认模型（如 deepseek-chat、deepseek-coder）

**设计要点：**
- 配置存储在providers.json文件中
- API Key加密存储，保障安全性
- 支持配置导入/导出功能

### 3. 对话界面模块

**界面风格：** 参考Claude Code和Codex的简洁风格

**核心功能：**
- **基础对话：** 消息发送/接收、Markdown渲染、代码语法高亮
- **会话管理：** 多会话切换、历史记录、会话重命名、删除
- **工具调用可视化：** 显示AI调用的工具、参数、结果
- **文件操作集成：** 文件上传/下载、代码文件预览

**界面布局：**
```
┌──────────────┬────────────────────────────────┐
│              │  对话头部（模型信息、操作按钮）  │
│   会话列表   ├────────────────────────────────┤
│              │                                │
│   - 新建     │        消息区域                │
│   - 会话1    │   - 用户消息                   │
│   - 会话2    │   - AI响应（含代码高亮）        │
│   - 会话3    │   - 工具调用可视化              │
│              │                                │
│              ├────────────────────────────────┤
│   当前模型   │  输入区域（消息输入、发送按钮）  │
└──────────────┴────────────────────────────────┘
```

**设计要点：**
- 默认浅色主题，支持深色/浅色/跟随系统三种模式
- 左侧会话列表 + 右侧对话区的简洁布局
- 代码块使用语法高亮显示
- 工具调用使用特殊样式展示
- 显示当前使用的AI供应商和模型

### 4. 数据存储模块

**存储方式：** SQLite数据库 + JSON配置文件

**数据结构：**

SQLite数据库存储：
- **会话表（sessions）：** 会话ID、标题、创建时间、更新时间、供应商ID
- **消息表（messages）：** 消息ID、会话ID、角色、内容、时间戳
- **工具调用表（tool_calls）：** 调用ID、消息ID、工具名称、参数、结果

JSON配置文件存储：
- **供应商配置（providers.json）：** 供应商列表，包含名称、API类型、端点URL、默认模型等
- **应用设置（settings.json）：** 主题、语言等应用级配置

**设计要点：**
- 对话数据使用SQLite存储，支持高效的查询和检索
- 配置数据使用JSON文件存储，便于备份、迁移和手动编辑
- API Key加密存储在JSON配置文件中

3. **简单会话管理**

   - 切换会话
   - 会话历史记录

4. **数据持久化**
   - SQLite存储对话历史
   - JSON存储配置

## 技术选型理由

| 选择 | 理由 |
|------|------|
| Tauri 2 | 轻量级、性能好、系统集成能力强、插件系统完善 |
| React | 生态丰富、组件库多、社区活跃 |
| TypeScript | 类型安全、开发效率高、代码可维护性好 |
| SQLite | 性能好、支持复杂查询、数据结构化 |
| 主题系统 | 默认浅色，支持深色/浅色/跟随系统，满足不同场景需求 |

## 风险和挑战

1. **CLI API兼容性：** 不同CLI工具的API可能有差异，需要适配层处理
2. **流式响应处理：** 需要正确处理AI的流式输出
3. **错误处理：** 网络错误、API限流等需要妥善处理
4. **数据安全：** API Key需要加密存储
