# 电脑控制（Computer Use）使用指南

CodeMUX 的电脑控制让智能体在**你批准之后**操作浏览器与桌面：从看懂页面到点原生应用的按钮。
本指南写的是使用者视角的行为（开关在哪、什么时候要批准、屏幕上的提示条与 Esc 意味着什么），
设计口径见 [`docs/specs/2026-10-07-computer-use.md`](../specs/2026-10-07-computer-use.md) 与
[`docs/specs/2026-10-10-computer-use-activity-authority-in-daemon.md`](../specs/2026-10-10-computer-use-activity-authority-in-daemon.md)。

## 两级能力

- **浏览器级**（设置 → 浏览器控制）：内置 `codemux-control` MCP 的浏览器工具族（10 个）——
  页面快照、元素级点击/输入/滚动、脚本执行等，**不碰系统键鼠**。
- **系统级**（设置 → 电脑控制：总开关 + 允许范围 + 步数上限 + 系统级执行）：桌面工具族（14 个）——
  桌面/窗口截图、窗口与元素清单、点击、拖拽、滚动、按键、输入、等待。真实动作由一个独立驱动子进程执行，
  由 daemon 管它的生命周期（拉起、健康检查、更新、急停时杀进程）。

两条刹车线一直有效：默认步数上限、单步超时；连续多步没有变化会自动停下。

## 审批

审批的**颗粒度**由设置 → 电脑控制 → 「审批方式」决定（默认最严格）：

- **逐次确认**（默认）：只读观测按会话记住；每一步输入动作都问一次，也可以点「允许 N 分钟」
  给一次**限时授权**（只在当前回合作数、到期或按 Esc 即失效）。
- **本会话记住**：只读观测免问；非敏感输入首次问一次，选「本会话记住」后本会话内同类动作不再问。
- **持久放行**：只读观测免问；非敏感输入不再逐次询问（设置本身即你的同意）。开启前会再确认一次。

无论哪个档位，这三条不变量都不变：

- **敏感场景**（登录、支付、验证码、密码、删除、关闭防护）**永远逐步确认** —— 宽松档位、会话记忆、
  限时授权都不认。
- **受保护目标**（密码管理器、终端、安全中心、CodeMUX 自身等）硬拒，允许列表写了也没用。
- **步数上限**照常（输入动作计数，到顶停下等你接手）。

这些是 CodeMUX 闸门自己的口径，与智能体的权限档位无关：输入动作在智能体任何权限模式（含 `full-access`）
下都不豁免。

- 没人能应答时不会白等：控制面里没有任何界面、且这个会话也没有界面在订阅时，daemon 立刻按
  `no-ui` 收口；只有在「可能有人看到」（桌面壳在跑，或有人正开着这条会话）时才保留完整的 120s 等待窗口。
  唯一能展示审批卡的界面断开时，挂起的放行按「放行界面已断开」收口。

## 「CodeMUX 正在操作电脑」提示条与全局 Esc 急停

**什么时候出现**：只要 daemon 报「这台机器正在被驱动」就出现 —— 判据在 daemon，不在界面。
因此**没人开界面时它照样出现**：后台会话、定时任务、从手机/PC 浏览器发起的操作期间，桌面上都会挂着这条提示。
这是 0.4.x 起的行为变化（此前它跟随桌面界面自己算出的窗口，没人开界面时你既看不到提示、也按不到急停）。

- 提示条显示在**光标所在的显示器**，置顶；隐藏是播完离场动画后隐藏，窗口保留复用（下次显示立刻出现）。
- **什么时候消失**：回合结束/被中断会立刻收起；即便回合还在跑别的事，只要 **30 秒**没有新的驱动动作，
  也会自动收起并释放全局 Esc（下一次 CUA 动作重新点亮）。等待你放行期间不熄 —— 那段时间是你正在决定。
- **按一次 Esc** 会一次停三件事：杀驱动子进程（在途动作立刻断）、收回该会话的限时授权、打断有活动的回合。
  没有人开界面时这三件事同样成立。

**注意：驱动期间 CodeMUX 会占用本机全局 Esc。** 只要有电脑控制在飞（含后台/无人值守的回合），
这个键就被 CodeMUX 接管，其它应用里的 Esc 也会被拿走；操作结束、回合结束或活动转假后立即释放。
只在有真实驱动动作时接管，平时不占。

**Fail-hidden（宁可收起，也不挂一条按不动的提示）**：

- 提示条只有在**真的武装成功**时才显示；全局 Esc 被别的程序占用时注册失败，此时不显示提示
  （设置页的停止按钮仍然可用）。
- 壳与 daemon 的控制面链路断开（含 Ping/Pong 保活判出的假死）只会「收起提示条 + 解除 Esc」；
  渲染进程崩掉、卡死或根本没加载，都不再影响这台机器上的提示与急停 —— 武装只剩 daemon 一个来源，
  渲染层不再举手，也就不存在「它比提示条先死」的问题。
- 链路不在时**不接管**：daemon 不可达意味着 Esc 按下去停不了任何东西 —— 绝不挂一条按不动的提示。

## 怎么停

- **按 Esc**（全局）：无人值守时也能用，见上。
- **界面里的停止**：会话/设置页的停止按钮，等价于打断当前回合。

## 事后取证

驱动、授权与急停都进审计日志：`GET /api/computer-use/audit`（需要 Local Daemon Token）返回
`{"ok":true,"entries":[…]}`，其中 `op` 会把「只停了机器」（`driver-estop`）与
「连驱动、授权和回合一起停」（`estop`）区分开。
