# 02 — 急停端点：一次调用把驱动、授权与回合一起停下

**What to build:** daemon 新增急停端点 `POST /api/computer-use/estop`（鉴权与既有电脑控制端点一致）：一次调用完成三件事 —— ①杀驱动子进程；②收回全部限时授权（沿用工单 13 的语义：刹车要一次踩到底，不能留「授权还在、随时能动」的尾巴）；③打断**所有当前有电脑控制活动的会话**。返回被打断的会话 id 列表，并写一条审计记录。

关键在于③由 daemon 自己决定打断谁：今天的「打断回合」那一半要经过渲染层回话，没人开界面时按 Esc 只能杀驱动、停不了回合。既有端点 `POST /api/computer-use/driver/estop`（只杀驱动 + 收回授权）保持可用，行为不变。

**Blocked by:** 01 — 活动真值：daemon 自己知道「这台机器正在被驱动」

## Decisions

- **新端点，不动旧端点**：`/computer-use/driver/estop` 只停机器（杀驱动 + 收回授权），行为保持原样；`/computer-use/estop` 是它的超集外加「打断回合」。旧端点仍被壳的当前 Esc 路径使用，删它会连带改掉 03 之前的行为。
- **打断谁的判据是工单 01 的活动真值**：先取一次快照钉住会话列表 —— 打断过程本身会把活动清掉，清完再取就空了。
- **打断失败也算「停下来了」**：会话已经不在了（被删、时间线丢了）时 `interrupt` 会报错，但急停的目标是「这台机器上没有回合在驱动」，不是「每个会话都还在」。这种情况仍然把回合与活动收掉，否则提示条会挂着不走 —— 停下来就要停干净。
- **收尾兜底 `clear_all` + 发布**：即使一条打断都没走到（例如标记被判成陈旧），急停之后也不该还留着活动。
- **审计动作名 `estop`**：与 `driver-estop` 分开，事后能分清「只停了机器」还是「连回合一起停了」。
- **响应用 `killed: false` 表示「没有驱动在跑」而不是错误**：急停的语义是结果状态（现在没有东西在驱动），不是「必须杀掉了一个进程」。
