# 02 — 组折叠状态机与应用运行期状态

**What to build:** 把过程组的展开/接管状态从组件内局部状态升级为应用运行期 UI 状态：满足门槛的组默认一律折叠，用户接管后任何自动事件都不翻转，跨会话切换、卸载与精简切换保留，应用重启回默认。本票只落状态与测试，不改 UI 行为（主线程接入在 04）。

**Blocked by:** —

**Status:** done（代码与自动化验证完成；dev:desktop 手工验收未执行）

- [x] 状态键＝会话身份（子智能体轨道追加子智能体身份）＋ 稳定段身份（`runKey`）。
- [x] ≥2 可见步骤的组初始一律默认折叠，无论历史 / 实时 / 成功 / 失败 / 中断；新出现的独立组不继承上一段的选择。
- [x] 首次用户点击写入「已接管 ＋ 目标状态」；此后流式追加、工具状态变化、段闭合、Turn Outcome 都不得改变它。
- [x] 切换 Session、尾部窗口卸载、离屏渲染、切换「精简 AI 输出」都不清除状态；切换设置只影响整轮外层显隐。
- [x] 会话或子智能体数据清理时同步清理对应条目，避免无界增长。
- [x] 不写入 Daemon / SQLite / localStorage / 应用配置；应用重启后全部恢复默认折叠。
- [x] 单步骤段不写入组状态（无组头、无组状态条目）。
- [x] 状态层测试：接管后追加保持、段完成保持、会话切换往返保持、精简切换保持、清理移除、跨子智能体不串 key。
- [x] 受影响测试全绿；不涉及 Rust daemon / Sidecar。
