# 02 — 解析规则统一与四来源覆盖

**What to build:** 让产物汇总对**所有 Agent Kind**、**所有来源路径**都算得准、算得全、算得一致。

这是本次的主体。当前解析规则两侧各写一份且都不全，导致四类用户可见问题：批量编辑完全消失、补丁类改动完全消失、pi 从来没有卡片、工具参数分帧到达时静默漏报。同时两侧行数语义相反，同一个改动在实时与刷新后可能给出不同数字。

本工单把「工具调用 → 产物条目」的解析收敛成一套规则并落到两侧，覆盖全部来源与工具形状。

**三条来源路径**（同一逻辑操作在不同来源下携带不同的名字形态与载荷形状，必须同时成立）：

| 来源 | 工具名形态 | 变更前快照 |
|------|-----------|-----------|
| 实时 | 部分被小写化，部分原样透传 | Claude Code 与 OpenCode 有；pi 没有 |
| 原生会话同步 | **保留上游原始拼写与大小写** | **一律没有** |
| 库内既有时间线 | 取决于写入当时 | 视当年而定 |

### 解析规则

- [x] 工具名匹配改为**大小写不敏感**（这是正确性要求：原生会话同步路径原样透传上游拼写，丢掉大小写归一会让整条同步来的会话失效）
- [x] 显式别名表覆盖已知写入类工具名的变体（含带前缀的 MCP 形式）；未命中时用模式兜底匹配写文件语义
- [x] 兜底匹配到的工具**仍必须解析出文件路径**才计入，避免把参数恰好含路径的非写文件工具误算成产物
- [x] 路径提取递归下钻工具入参，穿透嵌套壳（深度设上限），接受多种路径字段拼写；同时支持从补丁正文解析被操作的文件
- [x] 路径拼写归一（额外补的一条正确性要求）。真实数据回归查出两类分歧：前斜杠形态的 Windows 绝对路径被当成相对路径、又在前面拼一次 cwd；反斜杠形态的 cwd 与相对路径拼出 `D:\x/src/app.ts` 这种混合拼写。卡片按 `file` 去重，这两种都会让同一个文件出现两条。两侧现在都统一成前斜杠，并有构造用例钉住。

### 覆盖补全

- [x] **批量编辑**被识别（入参含多个编辑片段），实时与同步两种形状都算，折算成同一文件的一条条目
- [x] **补丁类工具**打通，三种载荷形态都产出正确条目：实时结构化变更数组、实时自由文本补丁、同步的嵌套补丁正文；正文行以空格开头（上下文行有前导空格）不得被裁剪；一段补丁涉及多个文件时每个文件各一条；新增/更新/删除三态归类正确并写入产物事件
- [x] **pi 接入**：其会话开始产出产物事件（当前零产出），写入与编辑均计入
- [x] **参数分帧到达**不再漏报：汇总器按工具调用标识累积入参而非只信任第一帧；参数后到时仍能建立基线；「分帧到达」与「一次到齐」产出**完全相同**的条目；参数始终缺失时安静跳过

### 一致性

- [x] 两侧行数语义统一为「按换行切分、丢弃末尾空行」，历史上分歧的 4 个尾随换行用例转为两端**逐字节一致**
- [x] 前端展示的增删行数与用户点开的 diff 内容一致（不再出现「卡片说改了 2 行、diff 里只改了 1 行」）
- [x] 用真实会话数据回归：库中同时带变更前后文本的条目两侧统计一致，已知的历史分歧条目全部转为一致
      做法升级为更强的形式：用**生产入口**（sidecar 的 `synthesizeTurnArtifactSummaries` / daemon 的 `inject_turn_artifact_summaries`）跑真实轮次切片。修复前 198/232 轮有分歧，修复后 **0/232**（636 条条目逐字节一致）。这一步额外查出四个 fixture 未覆盖的真实分歧，详见核查笔记。
- [x] 明确记录一个**不修**的已知差异：CRLF 与 LF 的整文件互转在两侧都计成全文件行数变更（Windows 上编辑器翻转一次换行符即触发）

### 退化基线（不是容错分支）

- [x] 无快照时的前后文本由编辑片段自身拼出，且**与快照路径同等测试覆盖**——原生会话同步来的轮次一律没有快照，pi 的实时轮次也没有
- [x] 无快照下的批量编辑与 pi 编辑产出可用的前后文本与正确行数

### 收录真实数据后才暴露的一条语义（本工单新增）

- [x] 同一文件在同一轮内被编辑多次时，**后续编辑必须作用在本轮已产出的内容上**，条目给出整轮净变化；每个 hunk 都套回本轮起点快照的实现会静默丢掉第二次及以后的编辑，卡片停在第一次编辑的中间态。附带：一轮结束时回到起点的文件要从卡片上撤下（净零过滤必须能撤销先前已放入的条目），这是「没有成功变更的轮次不产出卡片」的落地方式。

### 附带清理

- [x] 按既有迁移模式删除从未被任何代码读写的死表，带迁移测试；确认在**已有数据的库**上执行不失败，且全仓库仍无引用
      `turn_artifacts`：当前 schema 已不再创建它，但真实库里仍残留（0 行、全仓库零引用），按 `schema.rs` 既有 `DROP TABLE IF EXISTS` 位置清理，迁移测试断言清理后 `sqlite_master` 中不再存在。

### 边界

- [x] 本工单**不**改变卡片外观、文案与交互（不新增分组、不加状态徽章、不加第二个动作按钮）
- [x] 本工单**不**改变轮次边界（一轮一张卡片由工单 03 负责）
- [x] 本工单**不**回填历史数据：修复前已发生过的空参数调用、以及历史轮次缺失的条目均不在范围内
