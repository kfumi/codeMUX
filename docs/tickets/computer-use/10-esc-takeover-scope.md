## Comments

- **为什么收窄**（证据来自 PI-Desktop 的 `cn.star.computer-use` 插件，本机路径 `~/.pi-desktop/plugins/installed/`）：
  - 它同样需要一个人能按的硬中断：提示条文案就是「AI 正在控制你的电脑进行作业，可以按 ESC 强行打断」—— 说明这是这类产品的共同需求，不是过度设计。
  - 但它的提示条进程（`overlay.js` + `scripts/windows-banner.ps1`）**只在 `beginControl()` / `endControl()` 包住的那一次动作前后存在**，动作结束 400ms 就被杀 —— 抢键窗口是秒级，而不是「开关开着」的天级。我们旧实现的窗口开得太宽，本票补上。
  - 它的钩子用 `WH_KEYBOARD_LL` + `LLKHF_INJECTED` 过滤，**只认物理按键**：驱动自己注入的 Esc（智能体在目标应用里按 Esc）不会误触发急停。
  - 它的停止是协作式的（置 `stoppedByUser`，之后的动作一律 `stopped_by_user / not_sent`），不杀进程；我们保留更硬的**进程级急停**（杀驱动子进程，在途动作直接断）。
- **已知边界**：Electron 的 `globalShortcut` 是 OS 级热键注册，不区分物理按键与注入按键，因此**智能体经驱动注入的 Esc 也可能触发急停**。要拿到 PI 那样的过滤得改成自建低层键盘钩子（原生 helper 或放进驱动侧），本期先按「收窄窗口 + 可见提示」处理，真踩到再换。
- **提示条为什么跟随武装结果而不是跟随请求**：提示条上写着「按 Esc 急停」。若这个键被别的程序占着（浏览器、输入法、游戏都可能占 Esc），注册会失败，此时显示提示条等于骗用户。
- **收窄到什么程度**：当前判据是「有回合在跑 + 系统级执行开启」。更细的窗口需要「智能体真的在操作桌面」这一事实（驱动在跑 / 正在发 computer-use 工具调用），daemon 目前不对外发布；若以后要，可在 daemon 侧对 computer-use 工具调用发事件，渲染层据此再收窄。
- **2026-10-09 跟进（用户实测：一发消息就弹「正在控制这台电脑」）**：判据不再依赖「有回合在跑」，改为「**真的有 `computer_*` 工具在飞**」——工具调用已发出、结果未回（含审批等待），加上子智能体时间线里的同类调用；并要求电脑控制总开关也开启。纯聊天回合不再武装、不再显示提示条。提示条改为**显示上限 1s 自动收起**（同一次连续活动期间不重复弹），提示条窗口开 `setContentProtection(true)`（Electron 33 → Windows `WDA_EXCLUDEFROMCAPTURE`），driver 的 `computer_screenshot` 拍不到它——上一条里「若以后要，可在 daemon 侧发事件」的候选方案不再需要，渲染层用现成的 `turns.pendingToolIds` 即可判定。
- **2026-10-09 晚 工单 15 取代「1s 自动收起」**：提示条改为跟随整段桌面操作常驻 —— 武装判据从「`computer_*` 工具在飞」放宽到「本回合里出现过 `computer_*` 调用」（同一回合内黏住），回合结束才收；窗口位置从「工作区 17% 高度居中」改为「顶部下方 28px 居中」，样式对齐参考实现（ZCode）的顶部指示条。上面那条「显示上限 1s 自动收起（同一次连续活动期间不重复弹）」由此不再成立；同一条里 `setContentProtection(true)` 的结论不变，而且现在它是「截图里没有提示条」的唯一依靠。
