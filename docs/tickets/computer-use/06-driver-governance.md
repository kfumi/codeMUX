## Comments

- **设置页**（设置 → 电脑控制）：总开关、系统级执行、步数上限（1-200，与 daemon 校验同源）、驱动状态（命令/版本/工具数/最近错误）、重新检测/启动/一键诊断/急停/更新、驱动命令与参数、更新命令、允许列表（逐行，保存即生效）、内置拒绝范围（daemon 不可达时回退展示，保证「不可删除」始终看得见）。
- **诊断**：七项检查（已配置/平台受支持/进程存活/MCP 链路/**权限够用**/升级通道/拒绝列表就位），失败项都带「怎么修」。权限项把驱动报出的权限类错误（Access is denied / 拒绝访问 / elevation…）翻成「以管理员身份重启」的可执行建议。纯函数 `diagnose()`，单测逐项覆盖。
- **步数上限真的会停**：评审发现原实现只把 `max_steps` 写进配置与界面文案、没有任何计数——设置页的承诺是空的。现在闸门按会话+回合计数输入动作，到顶拒绝并给出汇报话术（集成用例：上限 2 时第三步直接 403「步数已到上限(2 步)」且不再弹放行）。设置页文案同步改为「一轮对话里输入动作的上限」。
- **更新必须确认**：接口层强制 `confirm: true`（不是靠界面自觉），界面走仓库既有的 `ConfirmDialog`（不是 `window.confirm`），执行用户配置的更新命令前先停驱动，并整条进审计。
- **急停两条路**：设置页按钮 → `POST /api/computer-use/driver/estop`；全局 Esc → 壳侧 `emergency-stop` 服务（`globalShortcut`）。**只在「系统级执行」开启期间武装** —— 全局 Esc 会抢走所有应用的 Esc，平时装着它等于替用户决定 Esc 归谁；触发时先通知界面打断回合，再杀驱动子进程，两件事都不经模型。
- **允许/拒绝**：`computer_use::policy` 纯函数；内置拒绝永远优先（允许列表写 `codemux` 也拦），空允许列表 = 除拒绝外全部可操作。拒绝判定同时用于桌面只读观测（不可操作窗口既不截图也不列举）。
- **审计**：`browser_automation_audit` 表补 `tool`/`actor`/`decision` 三列（旧库自动迁移）；每次执行尝试、每次审批决策、驱动启动/急停/更新各记一笔，含会话归属。
- **已知边界**：第三级的「驱动工具面」尚未对智能体开放（本票验收不含），因此当前驱动动作只有生命周期三件套；工具调用接入时走同一条审计与闸门路径。系统级执行开关现在的作用是：驱动启动的前提 + 全局 Esc 的武装条件 + 诊断里的平台提示。
