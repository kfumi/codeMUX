**What to build:** 智能体经批准能看桌面截图与活动窗口信息；用户也能手动截一屏贴进会话；只读工具与输入工具分权，隐私默认安全。

## Comments

实现完成，真机演示留待联调（需要真实模型与真实报错窗口）。

- **壳侧**：`desktop-capture.ts` 用 `desktopCapturer` 实现窗口清单/截图/活动窗口（依赖注入，Node 契约测试 10 条）；长边收敛到 1920 避免一张 4K 图撑爆上下文；`desktop-capture-host.ts` 是 Electron 适配层，活动窗口在 Windows 上经 PowerShell 读 user32 前台窗口，读不到就明确报错（不拿别的窗口冒充）。
- **工具面**：三个工具挂在既有内置 MCP server 上（`computer_windows` / `computer_screenshot` / `computer_active_window`），与浏览器级共用一条执行链路；截图以 MCP `image` content 回传。
- **开关分权**：桌面只读走「电脑控制」开关，浏览器级走「浏览器控制」开关；开一个不等于开另一个。
- **拒绝而非打码**：只读观测没有像素级识别能力，所以对拒绝列表内的窗口（密码管理器/终端/锁屏/安全中心/宿主自身）不截图、不在清单里列举；前台窗口属于这些范围时整体拒绝，且**不复述窗口标题**。**整屏截图同样受限**：截图时附带前台窗口标题，前台是受保护应用就拒绝整屏（否则密码管理器会被一并拍进去）。像素级打码需要驱动层（第三级）能力，属下一增量。
- **评审修正**：来源类型原先按 `display_id` 推断，而 Electron 不保证窗口源没有 `display_id` —— 推断错会让受保护窗口绕过筛查。现改为「这个来源出自哪张清单」，并补了对应断言。
- **脱敏**：轨迹与审计不落按键/输入原文（`redact_params`，参数值换成字数）；前端审批卡只显示「输入 N 个字符」。
- **手动贴屏**：输入框左侧相机按钮（`computer.capture` 能力，浏览器/移动形态自动隐藏），截主屏作为图片附件贴进当前会话，不经 daemon 闸门（用户主动发起的只读动作）。
- 门禁：同上；另 10 条壳侧截图契约测试、2 条 base64→附件转换测试。
