## Comments

- **现场**（会话 `0e7ea7dc` 第一轮，用户要求「使用电脑控制打开 FumiGit 并截图」）：13 次调用里 5 次返回 `"null"` 且 `isError=false`，模型据此判断「截图能力不可用」，改用 bash 兜圈。审计表里有一一对应的 5 条 ok=0：`前台窗口属于不可操作范围(CodeMUX 进程家族)，整屏截图会把它一并拍下…` —— **拒绝是对的，理由丢了**。
- **根因**：自动化接口失败时回 HTTP **200** + `{ok:false, error}`（`browser_automation.rs`），而 MCP 工具层只按状态码判断、直接取 `body["payload"]`（`browser_mcp.rs`）→ `Value::Null` → 工具报「成功但空」。修法就是先看 `ok`，失败把 `error` 冒泡。
- **措辞那一条是我自己引入的**：工单 11 把身份判定放在标题之前，于是标题就写着 CodeMUX 的窗口也报「按进程身份拒绝」。现在改为标题优先（人类可读、能解释是哪条规则），身份仅在标题挡不住时出手。
- **为什么要给坐标**：真实会话里窗口截图 1668px、窗口矩形 1296px（DPI 虚拟化），模型只能自己算缩放系数，第一次点击落在空白处。现在 `bounds`/`windowBounds` 与工具描述里的换算公式一起给出，缩放由数据说话。
- **技能刷新为什么要动**：内置技能原先「文件已存在就跳过」，意味着操作规范的任何更新都到不了已有安装（用户机器上就是这种情况）。新规则：镜像副本证明是我们写的且没被改过 → 刷新;旧安装没有镜像但 frontmatter 自称同名技能 → 认领;其余（用户改过、磁盘导入的同名技能）一律不动。
- **本票未做**（留给下一票）：桌面**输入**工具面（click / type / press_key / launch_app / list_apps / wait_for）与「bash 注入输入绕过审批闸门」这条旁路 —— 会话第二轮是模型自己写 C# P/Invoke `mouse_event` 完成点击的，审批与审计全程没参与。
