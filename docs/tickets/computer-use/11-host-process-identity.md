# 11 宿主进程身份硬拒（内置拒绝的第二半）

**What to build:** 桌面只读观测的「不可操作范围」除了按窗口标题串匹配，还要按**进程身份**拒绝宿主家族：daemon 自己、外壳（含它的渲染进程）、正在跑的驱动。标题可以没有（自绘无边框窗、驱动面板、DevTools），身份不会。

**Blocked by:** 04 桌面只读观测、06 驱动托管与护栏界面

**Status:** done

- [x] 壳侧新增窗口身份枚举（一次 `EnumWindows` + 一次 `Win32_Process` 快照）：句柄 → pid / 父进程号 / 映像名（`window-identity.ts` 解析与拼接是纯函数）
- [x] 窗口清单、窗口截图、整屏截图（前台身份）、活动窗口四类 payload 都带上身份；解不到就不带字段
- [x] 壳 spawn daemon 时经 `CODEMUX_SHELL_PID` 告知自己的 pid；daemon 另有自己的 pid 与驱动子进程 pid（`DriverHost::pid()`）
- [x] daemon 侧 `ProtectedProcesses::host_family` + `decide_window_access`：pid / 父进程号 / 映像名命中即拒绝，**允许列表覆盖不了**（与内置拒绝同一条铁律）
- [x] 映像名名单：`codemux`、`codemux-daemon`、`cua-driver`（大小写与 `.exe` 后缀不敏感）
- [x] 单测：无标题宿主窗口不进清单、壳的渲染进程按父进程号拒绝、宿主映像名即使写进允许列表也拒绝、第三方窗口（含良性标题）不受影响、非 Windows 没有身份时退回标题规则、整屏截图前台身份拒绝
- [x] 壳侧测试：身份枚举输出解析（坏行宁缺勿错）、来源 id ↔ 句柄拼接、四类 payload 的身份字段、枚举不可用时不带字段

## Comments

- **补的是哪个洞**：原先只按标题串匹配（`1password`、`powershell`、`codemux`…）。宿主的无边框窗口、驱动状态面板、DevTools 都可能没有标题或标题随手改，而空标题在当前规则下是**放行**的 —— 模型能列出并截到宿主自己的界面。文档里「内置拒绝包含宿主自身」这条承诺，只有标题挡得住，挡不住身份。
- **为什么父进程号也算命中**：Electron 的窗口属于**渲染进程**（pid 与外壳主进程不同），把外壳 pid 报上来并不能直接命中；渲染进程是外壳的子进程，一个父进程号就够。同理，开发模式下壳是 `electron.exe`，靠名字会误伤别的 Electron 应用（编辑器、聊天工具），所以名单里刻意没有 `electron`，那种情况由父进程号兜住。
- **为什么身份缺失时不拒绝一切**：非 Windows（或 PowerShell 不可用）壳报不出身份。此时退回原来的标题规则，而不是 fail-closed —— 否则 macOS/Linux 上桌面观测会整块不可用。这是有意的取舍，写在这里免得后人以为漏了。
- **成本**：每次窗口清单/截图多一次 PowerShell 调用（内联 C# 编译 + 一次 CIM 快照，约 0.5–1s）。没有加缓存：缓存的 pid 与句柄可能已经错位（句柄会被系统复用），身份判断宁可慢一点也不猜。
- **仍缺的一半（未做，故意）**：PI-Desktop 插件还有一条 —— 发送**破坏性按键**（Esc / Menu）前要有一份新鲜完整的目标树作为证据，树被截断时不能证明「没有弹窗」就拒发，防止误触取消下载、退出全屏、关页面这类不可逆副作用。我们当前**没有**任何把键盘事件发给操作系统的通路（驱动工具面尚未对智能体开放，见工单 06 的已知边界），所以这条无处可挂；它属于「驱动工具面」那一票的验收项，形状照 PI 的做法抄：动作前要新鲜快照、部分观察不得用于证明不存在、拒绝路径返回 `not_sent`。
