# 05 — 会话继承附加目录并注入四种智能体

**What to build:** 会话在创建或运行实例重建时，解析出「项目全部根减去该会话自己的工作目录」作为附加目录，并把这个清单写进智能体的环境说明。智能体第一轮就能看到这些绝对路径，可以直接读写，不需要用户每次提醒。

四种智能体种类使用各自最自然的追加位置，但**都不启用任何原生的多目录能力**。原因是 Claude 的 `--add-dir` 会把附加目录当作配置来源（加载其中的 `CLAUDE.md`、`.claude/`、skills），这违背本特性的核心约束：附加目录只贡献可访问的文件，不贡献项目规则。Codex 与 OpenCode 的同类能力各有自己的语义与版本兼容面，四家无法对齐，统一走提示词反而一致。

文案只写增量，不重复主目录，避免与各家自带的环境段出现两个互相矛盾的主工作目录：

```
Additional directories (outside the working directory):
  - <绝对路径>
Use absolute paths when reading or editing files in these directories.
```

附加目录为空时不输出该段。

失败语义：主根不可用则拒绝创建或重建会话；附加目录不可用时跳过该条、会话照常启动，并在界面提示。附加目录里的 `AGENTS.md`、`CLAUDE.md`、`.claude/`、项目 memory 一律不读取。

生效时机是每次运行实例重建（休眠唤醒、冷恢复、智能体种类切换、daemon 重启），运行中的一轮不变。
