# 09 右侧面板的凹面与卡片

**What to build:** 右侧面板（`SidePanel`）的平面关系对齐 Codex：面板主体是一层**凹面**（比表面低一档的「画布」），面板里的标签页与卡片回到抬高档浮在它上面；面板内所有控件的悬停反馈在浅色下要真的看得见。

**Blocked by:** 01

**Status:** done

- [x] 新增派生档 `--surface-canvas`（Codex 的 `--color-surface-canvas` = 表面往黑 2%）
- [x] 面板主体改用凹面；顶栏条保持表面档（Codex 的头部带比主体亮）
- [x] 标签页：激活档抬到 `--surface-1` + 描边，未激活档悬停浮出 ink
- [x] 空状态三张卡片：从 `bg-muted/45` 换成「`--surface-1` + 描边」
- [x] 面板内 22 处 `hover:bg-muted/*` 换成 ink 档（浅色下原先是**隐形**的）
- [x] 就近测试：派生冻结表补 `--surface-canvas`；右侧面板 111 条测试全绿

## Comments

对着 Codex 的右侧面板实机量测（浅色，无损抓图）反推出来的分层：

| | Codex 实测 | CodeMUX 改前 | 改后 |
|---|---|---|---|
| 内容面 | 255 | 252 | 252 |
| 面板主体 | **250** | 252（与内容面同色） | **247**（`--surface-canvas`） |
| 顶栏条 | 255 | 252 | 252（`bg-background`） |
| 激活标签页 | 255 + 发丝描边 | `bg-muted/45` → 251（几乎等于底色） | 253 + 描边 |
| 空状态卡片 | 255（在 250 上，+5） | `bg-muted/45` → 251（+1） | 253（在 247 上，+6） |

Codex 的关系一句话：**面板是凹的、卡片是平的（表面档）**。CodeMUX 原来主体与内容面同色、卡片又只比底色高 1 级，所以整块面板看着「没有卡片」——这就是「有点浅」。

**为什么用 `--surface-1` 而不是表面档当卡片**：浅色下两者都是 +5/+6（等价），但深色下 `--surface-canvas` 只比表面低不到 1 级（17 → 16.66，8bit 取整后仍是 17），表面档的卡片会退化成「只有描边」；抬高档（45）在深色下才读得出来，而且与 composer 用的是同一档 —— Codex 的 `elevatedPrimary` 本来就同时管这两件事。

**顺带清掉一个系统性毛病**：面板内 22 处 `hover:bg-muted/*` 在浅色下是**隐形**的 —— `--muted` 浅色 = 252，与它压着的底色（252/247）几乎同值，悬停完全没有反馈。全部换成 ink 档（`hover:bg-foreground/8`），与标题栏、图标轨、输入区同一套写法；深色下同样成立（ink 是亮的，悬停往亮走）。

## 代码评审修复

- 空状态标题的 `text-foreground/88`、卡片文字的 `text-foreground/82` 是 AGENTS.md 明令禁止的文字透明度后缀（浅色下 88% 只有约 3.9:1）。改成 `text-foreground`（17.2:1）。
- 顶栏「展开面板」按钮的焦点环 `ring-1 ring-ring/45` 压在近白表面上约 2:1，达不到 WCAG 2.2 SC 2.4.11 的 3:1；改成不透明 `ring-2 ring-ring`。
