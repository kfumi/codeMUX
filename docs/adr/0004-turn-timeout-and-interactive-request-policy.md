# Turn 空闲超时与交互请求策略

对话轮次不再使用"总时长硬超时"。空闲守卫只在引擎无进展且无未决交互请求时触发，中止当前轮并保留会话供重试。交互审批/提问默认无限期等待；无人值守场景可通过可配置的"单请求超时"自动拒绝/取消，绝不中止整个会话。该语义统一作用于三条运行时（Claude Code、Codex、OpenCode）。

## Status

accepted

## Considered Options

- **总时长硬超时**（原实现，OpenCode 路径 10 分钟不续期）——弃用：长任务在持续产出时被误杀，与主流工具（Claude Code、Codex、opencode 原生）的做法冲突。
- **超时后自动重试**——拒绝：会把"引擎无响应"静默掩盖、缺乏审计可见性；改为中止当前轮 + 可恢复，由用户决定是否重试。
- **审批/提问默认 5 分钟自动拒绝**——弃用：交互场景应无限等待人类；自动拒绝仅作为无人值守场景的可选配置。

## Consequences

- 空闲守卫是共享状态机（reset/suspend/expired，无 I/O），三条运行时共用同一语义。
- 未决交互请求挂起空闲守卫，避免"等待人类"被误判为"引擎停滞"。
- 超时中止仅作用于当前轮，会话与对话历史保留，可重试续上。
- 超时旋钮按 agent 档案的 `timeouts` 配置（`idle_timeout_ms` / `approval_timeout_ms` / `question_timeout_ms`，毫秒），并支持环境变量兜底。
