# 项目关联多源文件夹

**Status:** ready-for-agent

## Problem Statement

用户在做真实工程时，工作内容常常横跨多个文件夹：前后端分离的项目、monorepo 的多个包、主仓库加一个共享库。CodeMUX 现在只能把一个项目绑定到一个目录（`projects.path`），一条 Session 也只能在一个工作目录里工作。

由此产生的实际困扰：

- 用户被迫把「一个工程」拆成多个项目，侧栏里出现一堆本应属于同一件事的项目条目，项目级的置顶、排序、归档全部失去意义。
- 或者用户只建一个项目，然后在对话里反复粘贴另一个目录的绝对路径。智能体不知道那些路径存在，只能靠用户每次提醒；用户忘了提，智能体就只看得到一半代码。
- 定时任务与 Work Task 绑定项目时，也只能覆盖一个目录。
- 导入历史会话时，只能按单个目录匹配，横跨多个目录的旧会话无法归入同一个项目。

用户想要的心智模型是：**「这个工程由这几个文件夹组成」**，而不是「这个工程在哪个文件夹里」。

## Solution

项目从「一个目录」变成「一组源文件夹（Project Root）」，其中一个标记为主根。

- 创建项目时可以直接多选文件夹，一次建成多根项目。
- 「编辑项目」里可以增删文件夹、切换主根。
- 新建 Session 的工作目录仍是主根（保持行为可预测），但**其余根自动成为该 Session 的可达目录**，并且这个事实会写进智能体的环境说明，让智能体第一轮就知道有这些目录、可以直接用绝对路径读写。
- 主根变更、增删根都不改写已有 Session 的工作目录——历史对话保持原样。
- 附加目录只贡献「可访问的文件」，**不贡献项目配置**：附加目录里的 `AGENTS.md`、`CLAUDE.md`、`.claude/`、项目 memory 一律不读取，避免给项目加一个后端目录后，会话突然多出一套后端规则。
- 侧栏的 `@` 文件提及、文件树、项目浏览覆盖全部根；Git 面板、worktree、Git 环境快照只服务主根。
- 定时任务与 Work Task 在创建时冻结目录集合与主根，之后改项目不影响后台任务的写入范围。

## User Stories

1. 作为一个同时维护前端与后端的开发者，我想把两个目录放进同一个项目，这样侧栏不会因为「同一件事」出现两个条目。
2. 作为一个 monorepo 使用者，我想把 `packages/a`、`packages/b` 和 `packages/shared` 关联到同一个项目，这样一条对话就能同时改多个包。
3. 作为用户，我想在创建项目时一次多选几个文件夹，这样不用先建项目再逐个添加。
4. 作为用户，我想在「编辑项目」里添加文件夹，这样项目结构变化后不用重建项目。
5. 作为用户，我想在「编辑项目」里移除某个文件夹，这样不用把整个项目删掉重来。
6. 作为用户，我想把任意一个根设为「主要」，这样新建的对话默认落在我当前最常改的那个目录。
7. 作为用户，我想在移除主根后由剩下的文件夹自动接替，这样不用额外操作一次。
8. 作为用户，我想在移除文件夹时被告知有多少条会话会受影响，这样我能判断这个操作是否安全。
9. 作为用户，我想在移除最后一个文件夹时被引导到删除项目，这样不会留下一个没有落点的空项目。
10. 作为用户，我想让已有的对话在项目结构变化后仍能正常工作，这样整理项目不会破坏正在进行的上下文。
11. 作为用户，我想让新对话默认落在主根，这样行为可预测。
12. 作为用户，我想让智能体在第一轮就知道项目里还有哪些目录，这样不用每次手动告诉它路径。
13. 作为智能体，我想在环境说明里看到附加目录的绝对路径，这样我能直接读写而不必猜测。
14. 作为用户，我想让附加目录里的 `CLAUDE.md` 不被加载，这样加一个后端目录不会悄悄改变前端会话的行为。
15. 作为用户，我想让附加目录里的项目 memory 不被读取，这样两个仓库的规则不会互相打架。
16. 作为用户，我想在 `@` 里搜索到所有根下的文件，这样跨目录协作时不用手动输入路径。
17. 作为用户，我想让附加目录的 `@` 结果以绝对路径发送，这样文件不会被解析到错误的根。
18. 作为用户，我想在 `@` 候选里看到文件属于哪个根，这样同名文件我能分清。
19. 作为用户，我想让文件树与项目浏览显示所有根，这样我能看到项目的全貌。
20. 作为用户，我想让 Git 面板只显示主根的改动，这样多仓库项目下不会看到一个混乱的混合状态。
21. 作为用户，我想让 worktree 从主根切出，这样分支隔离的行为保持单一且可预期。
22. 作为用户，我想让定时任务在创建时固定目录集合，这样几天后无人值守运行时不会因为项目改动而写到意外的地方。
23. 作为用户，我想让 Work Task 在创建时固定目录集合，这样后台任务的范围不会漂移。
24. 作为用户，我想在附加目录不可用时照常开会话，这样某个目录被移走不会阻塞工作。
25. 作为用户，我想在附加目录不可用时看到提示，这样我不会误以为智能体还能访问它。
26. 作为用户，我想在主根不可用时被明确拒绝，这样我不会在一个没有落点的会话里浪费时间。
27. 作为用户，我想让导入历史会话按全部根匹配，这样跨目录的旧会话也能归入同一个项目。
28. 作为用户，我想让导入匹配不把 `frontend-old` 误判成 `frontend` 的子目录，这样导入列表不会出现错误候选。
29. 作为用户，我想让导入的会话保留它原本的工作目录，这样原生会话历史不会失联。
30. 作为用户，我想让同一个文件夹可以属于多个项目，这样共享库能同时被两个项目引用。
31. 作为用户，我想让父目录和子目录可以同时作为根，这样我既能看整个仓库也能单独把某个包设为主根。
32. 作为用户，我想让重复添加同一个文件夹被自动去重，这样列表不会出现两条一样的记录。
33. 作为用户，我想让文件夹列表显示目录名并在悬停时显示完整路径，这样列表不会因为长路径而不可读。
34. 作为用户，我想让同名文件夹在列表里仍然可分辨，这样我不会点错。
35. 作为用户，我想让文件夹顺序保持为添加顺序，这样主根继任规则是可预测的。
36. 作为用户，我想在侧栏看到项目有多个文件夹的标识，这样我能一眼分辨多根项目。
37. 作为使用移动伴侣的用户，我想在手机上也能看到并进入多根项目的会话，这样远程工作不丢失能力。
38. 作为使用定时任务的用户，我想在创建任务时看到它绑定的是项目的哪个目录，这样我知道任务会在哪里执行。
39. 作为开发者，我想让项目删除时连带删除其名下所有会话，这样清理是彻底的。
40. 作为开发者，我想让移除文件夹不改变会话归属，这样「整理结构」和「删除数据」是两件独立的事。
41. 作为开发者，我想让四种智能体种类的多根行为一致，这样用户切换智能体时不会遇到能力差异。
42. 作为开发者，我想让工作目录的解析只有一个权威实现，这样 worktree 会话不会在不同代码路径上拿到不同的目录。

## Implementation Decisions

### 领域模型

- **Project** 持有一组 **Project Root**，有序，其中一个为 **Primary Root**。
- **Session Working Directory** 是 Session 自己的属性，创建时写入主根路径，之后独立于 Project。
- **Additional Directory** = 项目全部根 **减去该会话自己的 cwd**（不是减主根）。因此导入会话或 worktree 会话的附加目录里可能出现项目主根，这是正确行为。
- **`project_id` 是 Session 归属的唯一判据**；工作目录只是执行位置，可能不在任何根内。

### 数据模型

- 新增 `project_roots(project_id, root_path, position, is_primary)`，主键 `(project_id, root_path)`，主键天然实现项目内按绝对路径去重。
- 主根唯一性由写入事务保证（先清 `is_primary`，再设一个），不使用部分唯一索引。
- `projects.path` 迁移后**删除**：迁移先把每个项目的 `path` 写成其主根（`position=0, is_primary=1`），再 `ALTER TABLE projects DROP COLUMN path`。保留冗余列会制造两个真相源。
- `sessions` 新增 `directory_scope`（JSON 数组，可空）：普通会话为 `NULL`（每次运行实例重建时现算）；生成型会话为最终附加目录数组，不含会话工作目录。
- `scheduled_tasks` / `work_tasks` 新增 `directory_scope`（任务创建时冻结的**全部项目根**）与 `working_path`（任务创建时冻结的主根）。运行建会话时用冻结主根作为 `sessions.working_path`，再用冻结根集合减去它得到 `sessions.directory_scope`。
- 旧任务（升级前创建）两列为 `NULL`：首次运行时按当时的项目根/主根补冻结并落库，之后不再漂移。
- 项目必须至少有 1 个根。

### 解析规则

会话工作目录的优先级（合并为唯一权威实现）：

```
imported 会话 → session_sources.cwd
否则         → sessions.working_path（生成型会话为任务创建时冻结的主根）
否则         → 项目主根（仅普通会话）
否则         → home
```

附加目录：

```
普通会话（directory_scope 为 NULL） → 项目当前根 − 会话 cwd
生成型会话（directory_scope 非空）  → 直接使用该数组（冻结根集合 − 冻结 cwd）
```

生效时机：普通会话在**每次运行实例重建时**解析（休眠唤醒、冷恢复、Agent Kind Switch、daemon 重启）；生成型会话直接使用任务创建时冻结的主根与根集合，不重新读取项目当前根。运行中的一轮不变。

### 注入

四种智能体种类都**不启用**原生多目录能力，只追加一段 system prompt。理由：Claude 的 `additionalDirectories` / `--add-dir` 会连带加载附加目录的 `CLAUDE.md`、`.claude/`、skills，违背「附加目录不贡献配置」这一核心约束；Codex 与 OpenCode 各有自己的语义和版本兼容面，四家无法对齐。

注入点：Claude 的 system prompt 追加字段、Codex 的 thread 初始化 instructions、OpenCode 的 `Config.instructions`（写临时说明文件）、pi 的 `--append-system-prompt`。

文案只写增量：不重复主目录、不出现 `# Environment` 标题，避免与各家自带的环境段重复或矛盾：

```
Additional directories (outside the working directory):
  - <绝对路径>
Use absolute paths when reading or editing files in these directories.
```

附加目录为空时不输出该段。

### 接口契约

- `Project` 的对外形状从 `{ id, name, path, created_at, updated_at }` 变为 `{ id, name, roots: ProjectRoot[], created_at, updated_at }`，其中 `ProjectRoot = { path, position, isPrimary }`。
- 创建项目的请求体从 `{ name, path }` 变为 `{ name, roots: string[], primaryRoot? }`：`roots` 顺序即添加顺序，`primaryRoot` 必须是 `roots` 之一，缺省时第一个为主根。重命名不变。新增一个编辑接口，接收 `{ name?, roots?, primaryRoot? }`。
- 前端所有「项目目录」读取点改为「主根」：Git 面板的路径参数、文件树、`@` 提及、导入匹配、Git 环境快照缓存键。
- daemon 的 Git 路由**继续接收路径参数**，不改成 projectId——worktree 会话需要对 worktree 路径做 Git 操作。
- `@` 提及：主根文件用相对路径作为发送值；附加目录文件用绝对路径；展示层单独显示根名徽标。
- 导入匹配改为遍历全部根 + 路径段边界判断（`cwd === root || cwd` 以 `root + 分隔符` 开头，Windows 大小写不敏感）。

### UI

项目编辑器（形态参考 ZCode）：

```
编辑项目
  项目名称  [____________]
  源文件夹
    📁 <目录名>                    主要    ×
    📁 <目录名>                  设为主要  ×
    ...
    📁 添加文件夹
  [删除项目]                [取消] [保存]
```

- 文件夹显示末级目录名，悬停显示完整路径；同名时在列表内消歧。
- 不做拖拽排序；顺序即添加顺序，`设为主要` 只改主根标记。
- 移除主根：剩余根中 `position` 最小者自动继任。
- 移除最后一个根：切到「删除项目」流程并提示将被连带删除的会话数。
- 移除非最后根：不改写任何会话，提示有多少条会话继续在原目录运行。
- 创建入口：原生目录选择器改为多选；选中后在创建对话框里确认项目名称与根顺序，第一个目录默认是主根，可用「设为主要」调整，确认后建成多根项目。

### 根范围归属

| 功能 | 范围 |
|---|---|
| `@` 提及、文件树、项目浏览 | 全部根 |
| 项目 Skill 扫描 | 只扫主根（v1 不读附加目录的项目能力） |
| Git 面板、worktree 创建、Git 环境快照 | 只服务主根 |
| 导入会话匹配 | 全部根，路径段边界判断 |

### 顺带修复的既有缺陷

- `companion` 侧存在一份只读 `projects.path`、忽略 `sessions.working_path` 的会话目录解析实现，导致 worktree 会话在「首发」与「移动端改设置后刷新 runtime」两条路径上拿到项目主根而非 worktree 路径。删列迫使两处合并，顺带修复。
- 导入匹配的前缀判断会把 `frontend-old` 误判为 `frontend` 的子目录。

## Testing Decisions

**什么算好测试**：只断言外部可观察行为。DB 层断言「存进去什么、读出来什么」；解析函数断言「给定输入产出什么目录数组」；sidecar 断言「发出的运行时参数里有没有那段文本」；前端断言「用户点了什么、界面/请求变成什么」。不断言内部字段名、私有函数、实现步骤。

**四层接缝，均为既有接缝，不新建：**

1. **daemon 内存 SQLite**（复用 `db/schema.rs` 已有的 `Connection::open_in_memory()` 迁移测试形态）：迁移把旧 `path` 搬进 roots 并删列；`project_roots` 增删改；项目内去重；主根唯一；移除主根后 `position` 最小者继任；移除最后根的行为。
2. **会话目录解析纯函数**（复用 `agent/session_lifecycle.rs` 已有的测试模块形态）：工作目录优先级（imported → working_path → 主根 → home）；附加目录 = 全部根 − cwd；生成型会话使用冻结的根集合与冻结主根；冻结主根不可用时运行失败；主根不可用与附加目录不可用的区分。
3. **sidecar 运行时配置**（复用 `codexAppServerRuntime.test.ts` / `opencodeSdk.test.ts` / `index.test.ts` 已有的「构造命令 → 断言发出参数」形态）：四种智能体各自把附加目录写进正确的字段；空数组时不输出该段；附加目录存在时不会启用任何原生多目录参数。
4. **前端 store 与组件**（复用 `projectStore.test.ts` 的 facade mock 形态、组件测试的 Testing Library 形态）：创建请求体形状；编辑器增删根与切换主根；移除最后根走删除流程；`@` 提及的主根相对路径与附加目录绝对路径；导入匹配的边界判断。

**不新建 REST 路由级测试**：`/api/projects` 目前没有路由测试，本特性也不新增。契约由前端断言请求体形状 + DB 断言落库结果两端对齐，中间层只做透传。

## Out of Scope

- 加载附加目录的 skills / commands / agents（后续独立票）。
- 跨根 Git 操作（多仓库 status / diff）。
- 会话级目录选择（新建会话工作目录恒为主根）。
- 文件夹拖拽排序。
- 任何智能体种类的原生多目录能力。
- 强制路径边界（把文件工具执行权收归 daemon）。本特性是文件夹组织，不是权限模型重构：在 Codex、OpenCode、pi 上，「项目只包含这些文件夹」是提示词级别的约定而非强制。
- 跨设备的项目根同步、远程 Host 的多根（当前只有本机 daemon）。
- 项目根的引用计数、隐藏成员等共享模型。

## Further Notes

- 设计过程见 [ADR 0020](../adr/0020-multi-root-via-prompt-only.md)（为什么只走提示词）与 [ADR 0021](../adr/0021-project-roots-replace-project-path.md)（为什么删掉 `projects.path`）。
- 术语以 [CONTEXT.md](../../CONTEXT.md) 的 Project / Project Root / Primary Root / Additional Directory / Session Working Directory 为准，不要在代码或 UI 里引入同义词。
- 与 ZCode 的关键差异：ZCode 自己拥有完整的 system prompt，CodeMUX 是往各家 CLI 自带的环境段里**追加**，因此文案必须只写增量，否则会出现两个互相矛盾的「主工作目录」。
- `rusqlite 0.31` 的 `bundled` 特性提供 SQLite ≥ 3.45，`ALTER TABLE ... DROP COLUMN` 可用，代码库已有先例。
- 验收要点：

| 用例 | 断言 |
|---|---|
| 多选目录建项目 | 一次选 3 个目录，建成 3 根项目，第一个默认主根、可用「设为主要」调整；重启后仍在 |
| 新建会话 | cwd = 主根；提示词包含另外 2 个根的绝对路径 |
| 改主根 | 已有会话 cwd 不变；新普通会话 cwd = 新主根；已创建的生成型任务仍用冻结主根与根集合 |
| 移除非主根 | 已有会话不变；该路径从附加目录消失；UI 提示会话数 |
| 移除主根 | `position` 最小者继任；已有会话 cwd 不变 |
| 移除最后一个根 | 走删除流程并提示会话数；确认后项目与会话消失 |
| 附加目录不可用 | 会话照常启动并提示；主根不可用则拒绝 |
| 四种智能体 | 附加目录路径出现在各自 system prompt；附加目录的 `CLAUDE.md` 未被加载 |
| 导入会话 | 按全部根匹配；`frontend-old` 不被 `frontend` 误匹配；cwd 用原生存储路径 |
| 定时任务 / Work Task | 创建时冻结目录集合与主根；之后改项目根/主根不影响它；冻结主根不可用时本次运行失败 |
