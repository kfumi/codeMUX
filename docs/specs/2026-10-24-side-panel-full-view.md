# 侧面板完整视图：主对话固定为首个标签

**Status:** ready-for-agent

## Problem Statement

用户点侧面板右上角的「展开预览」把面板放大成全内容区后，主对话就被面板**完全盖住**了：既看不到 agent 的输出，也没有任何入口切回去继续输入，只能先点「恢复面宽」把面板缩回去。完整视图本来的意义是「临时借用主对话的空间看审查/终端/浏览器」，但现在借出去就还不回来了——看一眼对话内容都要付出一次完整的布局切换。

参照 ZCode 桌面端的「Side Pane 完整视图」：面板占满内容区时，主对话自动变成 tab 栏里的**第一个固定标签**（不能关闭），点它就在面板内容区全宽显示主对话，点其他标签回到面板内容。空间借出去了，但对话始终一击可达。

## Solution

把现有的「展开预览」升级为「完整视图」：

- 面板展开占满内容区时，tab 栏**第一位**固定出现一个「对话」标签：会话图标 + 当前会话标题，**没有关闭按钮**、不参与右键菜单与拖拽，也不受「关闭其他/全部」影响——因为它不是标签数据结构里的一项，只是渲染期插入的固定项。
- 点「对话」标签 → 主对话（时间线 + 输入区）在面板内容区全宽显示；点任何面板标签 → 显示该标签内容，对话标签仍留在第一位。
- 切换只是**换定位方式**，主对话 DOM 不移动、不重挂载：草稿、光标、滚动位置、上传中的附件、运行中的权限卡片全部原样。
- 退出完整视图（恢复面宽 / 收起面板）后一切如旧：面板宽度、侧栏显隐、终端标签、会话状态都没有被碰过。

## User Stories

1. 作为用户，我希望点「展开预览」进入完整视图后，tab 栏第一位出现「对话」标签，这样我随时能点回主对话。
2. 作为用户，我希望对话标签显示会话图标和当前会话标题，这样在一排标签里一眼认出它。
3. 作为用户，我希望对话标签不能被关闭——没有 ×、右键菜单里也没有关闭项，因为它就是主对话本身。
4. 作为用户，我希望对话标签永远排在第一位，新打开的标签排在它后面而不是挤走它。
5. 作为用户，我希望点对话标签后，主对话连同输入区在面板内容区全宽显示，直接继续对话。
6. 作为用户，我从对话标签切回面板标签时，希望恢复我离开前选中的那个标签，而不是回到第一个。
7. 作为用户，我希望在完整视图的对话标签里输入、发消息、审批权限、回答 AI 提问，行为与普通视图完全一致。
8. 作为用户，我希望在对话标签与面板标签之间来回切换时，输入框草稿、光标位置、消息滚动位置、上传中的附件都保留，不丢失也不闪烁。
9. 作为用户，进入完整视图时当前面板标签保持激活（不强制跳到对话标签），这样展开面板看我正在看的东西时不被打断。
10. 作为用户，我希望在完整视图里关掉最后一个面板标签后，面板自动收起并退出完整视图，主对话回到原位——「面板里没有可看的东西了」就是收起它的信号。
11. 作为用户，我希望点「恢复面宽」退出完整视图后，面板宽度、侧栏显隐、终端标签一切如旧。
12. 作为用户，我希望收起面板（»）会同时退出完整视图；再次打开面板回到普通半宽形态，不残留完整视图。
13. 作为用户，我希望切到别的会话再切回来时，这个会话的完整视图开关与所在标签恢复原样。
14. 作为用户，我希望对话标签上的标题随会话标题自动更新（重命名或 AI 自动起标题后立刻变）。
15. 作为用户，我在完整视图的对话里点开文件 / diff / 子智能体预览时，希望新标签在面板里打开并自动切换过去，对话标签仍在第一位等我回来。
16. 作为用户，我希望对话标签激活期间，浏览器标签背后的原生页面不会盖在对话上面。
17. 作为用户，我希望正在流式输出的回合切到面板标签再切回来，输出、滚动位置、运行状态都连续不乱。
18. 作为用户，完整视图下没有打开任何面板标签时，tab 栏只有对话标签和「+」，内容区显示对话。
19. 作为用户，浏览器或手机形态访问时一切照旧——那里本来就没有完整视图入口。
20. 作为窄屏用户，我不受影响：窄屏的面板本来就是全宽覆盖，不出现对话标签。
21. 作为用户，用后退/前进在会话间导航时，完整视图状态按导航快照恢复，不出现「前进之后面板莫名展开」。
22. 作为维护者，我希望对话标签不进入标签数据结构，现有的关闭/重排/「关闭其他标签」逻辑零改动即可保证碰不到它。
23. 作为维护者，我希望「切到面板标签」的 surface 联动收口在 store 的 action 里，所有 UI 入口（tab 点击、「+」菜单、消息里的链接打开）自动一致，不依赖每个入口各自记得。
24. 作为维护者，我希望主对话 DOM 不移动、不重挂载（只换定位方式），编辑器草稿、Esc 停止等依赖焦点在对话 DOM 内的行为不被破坏。
25. 作为维护者，我希望退出完整视图是纯复位操作，不需要任何「进入前布局快照」的记录与回放。
26. 作为维护者，我希望完整视图状态与现有 scope 快照同一生命周期（内存态、随会话 scope 保存恢复），不新增持久化。

## Implementation Decisions

- **状态归属**：侧面板 store 是唯一 owner。scope 快照新增一个布尔字段（对话 surface 是否激活，默认 false）；「完整视图生效」= 面板打开且展开（现有两个状态），「对话标签激活」= 完整视图生效且该布尔为真，均为只读派生。退出完整视图（收起面板、恢复面宽、清空标签）时复位该布尔。
- **对话标签是渲染期固定项**：不进入标签数组，用保留标识区分；仅在完整视图生效且存在活动会话时渲染在 tab 栏第一位；无关闭按钮、无右键菜单、不参与关闭其他/全部。
- **surface 路由收口在 store action**：激活对话标签的动作置位布尔且**不改 activeTabId**（切回面板标签时恢复原选中）；现有的激活标签与所有「打开 xx 标签」动作在设置 activeTabId 的同时把布尔切回 false。关闭标签后的邻居继承激活同样维持面板 surface。因为收口在 store，无需像参考实现那样在每个 UI 入口包一层包装函数。
- **单实例与定位宿主**：主对话组件留在主布局的对话列，由一个常驻宿主层包裹。普通形态下宿主是普通布局容器（布局与现状一致）；对话标签激活时宿主切换为 fixed 定位，几何上覆盖侧面板的内容区（tab 栏下方的 slot），坐标由实测 bounding rect + ResizeObserver 写入宿主 style——这是 DOM 布局投影，不进 React state。侧面板通过回调 ref 把内容区元素交给宿主。对话 DOM 不移动、不重挂载（参考实现的不变量，防止草稿/附件/滚动/焦点出现两份或丢失）。
- **层叠与原生视图**：宿主的 z 序高于面板内容，但几何上只覆盖内容 slot、不覆盖 tab 栏（tab 栏在 slot 上方，保持可见可点）。对话标签激活期间，浏览器标签的原生视图可见性判定为「无激活 browser 标签」（沿用现有浏览器可见性联动链路），否则原生页面会盖在对话上面。内容面圆角裁剪对 fixed 子元素的实际行为在实现时实测，必要时宿主复用同一裁剪。
- **最后一个面板标签的关闭**：无论是否处于完整视图，关掉最后一个面板标签都按既有规则收起面板，并连带退出完整视图（复位展开态与对话 surface），主对话回到对话列——与参考实现同口径（2026-10-24 修正：初版曾按「保面板、落到对话标签」实现，验收时改回参考口径）。「收起面板」与「关闭所有标签」同样连带复位。
- **进入不换标签、退出零副作用**：进入完整视图保持当前面板标签激活；退出不修改面板宽度、侧栏、终端等任何原有状态——完整视图从头到尾没有写过这些值。
- **标题来源**：对话标签标题 = 活动会话的标题（侧面板的 scope 即会话标识），从会话 store 派生，随重命名/自动命名更新；无会话或新建草稿态不渲染对话标签。
- **导航快照**：对话 surface 布尔随 scope 快照一起保存与恢复（与面板开合、激活标签同一链路），后退/前进语义一致。
- **形态边界**：完整视图入口沿用现有展开按钮（窄屏本就隐藏），浏览器/移动形态不新增入口；第一期不做浮动输入窗、不注册快捷键（快捷键可后续经现有可配置键位系统追加）。

## Testing Decisions

- 好的测试只断言**外部行为**：标签渲染与否与顺序、点击后的可见内容、store 状态转移、浏览器可见性判定；不断言内部实现与像素几何（实测 rect 属于 DOM 布局投影，不是业务状态）。
- 全部使用现有接缝，不新增接缝：
   1. **侧面板 store 单测**（先例：store 自带的 colocate 测试）：surface 派生规则；激活对话标签不动 activeTabId；激活/打开面板标签连带切回面板 surface；完整视图下关最后一个标签收起面板、退出完整视图（2026-10-24 修正口径，见 Implementation Decisions）；快照随 scope 保存恢复；退出路径复位。
  2. **侧面板组件测试**（先例：现有组件测试 13 例）：对话标签的出现条件、排第一位、无关闭按钮、点击切换 surface；无活动会话不渲染；「+」菜单打开标签后自动切到面板 surface。
  3. **主布局/宿主测试**（先例：主布局测试 21 例，含源码级契约）：宿主在普通与对话两种形态下的定位模式切换；slot 元素经回调 ref 传递。几何断言到「fixed + 使用给定 rect」为止。
- 主布局改动波及面大：改动后除 colocate 测试外补跑 workspace 与 layout 目录相关测试；提交前按仓库门禁跑全量 vitest。

## Out of Scope

- 浮动输入窗（参考实现里的浮窗、最小化圆钮、回答气泡、拖拽吸附整套交互）。
- 完整视图的快捷键与设置页键位注册。
- 对话标签的拖拽排序、右键菜单、未读角标。
- 窄屏形态的完整视图入口。
- 窗口 chrome 改造（参考实现会隐藏工作区头部、让 tab 栏充当窗口顶栏；CodeMUX 的标题栏常驻，无需改）。
- daemon / Companion 协议侧的任何改动。

## Further Notes

- 参考实现：ZCode 桌面端 side-pane-full-view 模块及其行为合同文档。直接沿用的三条不变量：对话 DOM 单实例（只换定位不换挂载）；对话标签用保留值、不进标签注册表；退出完整视图零副作用（不记录也不回放任何「进入前布局」）。
- 两点已拍板（本期口径）：(a) 不做浮动输入窗——面板标签激活期间要看对话/要输入就切对话标签；(b) 完整视图下关最后一个面板标签即收起面板、退出完整视图（初版曾实现为「保面板、落到对话标签」，2026-10-24 按用户验收意见改回参考实现口径）。
- 实现期待实测的一个细节：内容面（content surface）的圆角 clip-path 对 fixed 定位子元素的裁剪行为，决定宿主右下角是否需要复用同一裁剪。
- 本特性为纯前端改动，不触 daemon；按仓库惯例，daemon 侧无重建需求。
