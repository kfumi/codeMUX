# 内置浏览器（Side Panel Browser）

**Status:** ready-for-agent

## Problem Statement

用户在 CodeMUX 里排查网页、对照 UI、给智能体描述页面结构时，只能把链接丢到系统浏览器，再手工复制文字或截图回来。侧边面板已经能打开审查、终端、文件等标签，但没有内置网页浏览。用户无法在同一窗口里打开页面、检查 DOM 元素，并把选中的网页元素作为当前 Session 的上下文发给智能体。

设置里也没有内置浏览器的资料管理（缓存、Cookie、证书校验），无法在本机安全地处理内置浏览产生的站点数据。

## Solution

在桌面端侧边面板增加一种 **浏览器面板**：用户不依赖当前项目也能打开。面板内部再管理多个 **浏览器页**（地址栏、前进/后退/刷新、多页标签）。页面由系统 WebView 以子视图嵌入，而不是 iframe。

用户可进入 **元素检查模式**：悬停高亮页面元素并显示标签名、尺寸、颜色、字体；点击后把该 **网页元素** 收成当前 Session Composer 上的可撤销引用。发送 User Message 时，这些元素序列化为结构化文本块，随正文一起交给当前 Agent Kind。

设置新增 **浏览器控制** 页：可忽略内置浏览器的证书校验（改后需重启），可清除缓存（保留 Cookie），或清除全部浏览器资料（不可撤销）。本规格不把「开启内置浏览器控制」做成打开侧边栏浏览器的前提；该开关留给后续智能体网页操作工具，首版只持久化、不改变浏览入口。

参考 Paseo 的分层（宿主、页元数据、元素选取、Composer 引用），但宿主按 Tauri 子 WebView 重写，不引入 Electron，也不接入第三方 Browser Use 库。

## User Stories

### 打开与入口

1. As a 桌面用户，我希望在侧边面板空状态看到「浏览器」入口，以便与审查、终端并列打开网页。
2. As a 桌面用户，我希望在侧边面板标签栏的「+」菜单里也能打开浏览器，以便已有其他标签时仍能补开。
3. As a 桌面用户，我希望打开浏览器后侧边面板自动展开并激活该浏览器面板，以便立刻看到地址栏和页面区域。
4. As a 桌面用户，我希望没有选中项目时仍能打开浏览器，以便浏览与当前仓库无关的网页。
5. As a 桌面用户，我希望本次不增加「辅助对话」标签，以便范围只覆盖内置浏览。
6. As a 桌面用户，我希望同一 Session 作用域内重复点「打开浏览器」时复用已有浏览器面板而不是再堆一个同级标签，以便侧边栏不被重复入口撑满。
7. As a 桌面用户，我希望切换 Session 时浏览器面板状态跟该 Session 的侧边面板作用域走，以便不同对话不串页。
8. As a 桌面用户，我希望关闭浏览器面板时内层各浏览器页一并销毁，以便不再占用 WebView 资源。
9. As a 桌面用户，我希望侧边面板的前进/后退导航能恢复「当时是否打开了浏览器面板」，以便与现有审查/终端行为一致。

### 浏览器页与导航

10. As a 桌面用户，我希望浏览器面板内部有独立的网页标签栏（含关闭、新建），以便同时打开多个站点而不占用多个侧边面板顶层标签。
11. As a 桌面用户，我希望点「+」新建浏览器页时得到空白页和空地址栏，以便自己输入 URL，而不是被强制打开某个搜索引擎。
12. As a 桌面用户，我希望在地址栏输入或粘贴 URL 后回车即可导航，以便像普通浏览器一样使用。
13. As a 桌面用户，当我输入没有协议的主机名时，我希望应用自动补上 `https://` 再导航，以便少记协议。
14. As a 桌面用户，我希望非法或非 http(s) 地址（如 `file://`、`javascript:`）被拒绝并给出可见错误，以便不会误开本地文件或脚本。
15. As a 桌面用户，我希望有后退、前进、刷新按钮，且在无法后退/前进时按钮呈现禁用态，以便状态诚实。
16. As a 桌面用户，我希望页面加载中地址栏或标签上有加载反馈，加载结束后消失，以便知道是否卡住。
17. As a 桌面用户，我希望标签标题随页面 `<title>` 更新，没有标题时显示主机名或「新标签页」，以便辨认多个页。
18. As a 桌面用户，我希望标签在拿到 favicon 时显示图标，没有时用地球占位图标，以便扫一眼区分站点。
19. As a 桌面用户，我希望在页面内点击链接（当前窗口导航）会更新地址栏，以便地址栏始终反映真实 URL。
20. As a 桌面用户，我希望关闭某一个浏览器页后激活相邻页，关到最后一个时保留一个空白页或关闭整个浏览器面板（实现须二选一并保持一致），以便不会留下空壳。
21. As a 桌面用户，我希望侧边面板拖拽改宽或展开覆盖主区时，网页内容区域跟着对齐，以便看不到错位黑边或把页面盖住聊天。
22. As a 桌面用户，我希望切到审查/终端等其他侧边面板标签时，已打开的网页被停放而不是销毁，切回来仍停在原来的滚动位置和登录态，以便来回对照。
23. As a 桌面用户，我希望折叠侧边面板时网页被隐藏，再次打开仍恢复，以便不丢页。
24. As a 桌面用户，我希望同一应用内所有浏览器页共享一份浏览器资料（Cookie / 本地存储），以便在一个页登录后另一个页仍保持登录。
25. As a 桌面用户，我希望地址栏右侧有复制当前 URL 的动作，以便把链接贴到别处。
26. As a 桌面用户，我希望溢出菜单里至少能打开该页的开发者工具（桌面调试场景）或明确不做时不放空按钮，以便工具栏图标都有含义。

### 元素检查

27. As a 桌面用户，我希望地址栏旁有一个检查按钮（魔杖/指针），以便一键进入元素检查模式。
28. As a 桌面用户，进入检查模式后，我希望鼠标在页面上悬停时目标元素出现高亮描边，以便确认选的是哪一块。
29. As a 桌面用户，悬停时我希望看到浮层：标签名、宽高、颜色、字体大小与字体族，以便快速读样式。
30. As a 桌面用户，我希望点击高亮元素后将其捕获为网页元素引用，并退出或保持检查模式直到我再点一次按钮 / 按 Escape（实现须固定一种，推荐 Escape 或再点按钮退出，点击捕获后保持模式以便连续多选），以便一次选多个。
31. As a 桌面用户，我希望按 Escape 退出检查模式且不捕获当前悬停项，以便误进模式能取消。
32. As a 桌面用户，我希望检查模式开启时检查按钮呈现按下态，以便知道现在点页面会捕获而不是普通点击。
33. As a 桌面用户，我希望检查模式只作用于当前激活的浏览器页，切换页时自动结束检查，以便不会点到另一页却写入旧页的元素。
34. As a 桌面用户，当页面尚未加载完成或导航中时，我希望检查按钮禁用或提示稍候，以便避免注入失败。
35. As a 桌面用户，当目标页拒绝脚本注入时，我希望看到失败提示而不是静默无反应，以便知道检查不可用。

### 网页元素与 Composer

36. As a 当前 Session 的用户，我希望捕获的网页元素出现在 Composer 附件/引用区，显示标签名和一段可见文本摘要，以便发送前确认选了什么。
37. As a 当前 Session 的用户，我希望引用区显示「N 个网页元素」，以便一眼看出数量。
38. As a 当前 Session 的用户，我希望可以单独撤销某一个网页元素，也可以一键清空全部，以便改主意。
39. As a 当前 Session 的用户，我希望这些引用绑定当前 Session 作用域：切到另一条 Session 看不到它们，切回来还在（直到发送或手动清除），以便不串对话。
40. As a 当前 Session 的用户，我希望发送 User Message 后这些网页元素随该条消息发出并从 Composer 草稿区消失，以便下一轮是干净的。
41. As a 当前 Session 的用户，我希望发出去的内容里包含页面 URL、标签名、可见文本和选择器（若有），以便智能体知道元素来自哪个页、长什么样。
42. As a 当前 Session 的用户，我希望网页元素作为 User Message 文本上下文发送，而不是新的图片 Attachment，以便不走 Attachment Enrichment，也不要求模型具备 Vision Capability。
43. As a 当前 Session 的用户，我希望聊天时间线里的 User Message 仍以可读方式保留这些元素摘要（至少在正文或专用块中），以便回顾时知道当时贴了哪些页元素。
44. As a 当前 Session 的用户，当 Composer 里已有图片 Attachment 时，我希望网页元素引用与图片预览并存，互不影响，以便同时贴截图和 DOM 摘要。
45. As a 当前 Session 的用户，我希望 Queued Message 若在排队前已带上网页元素文本，发送时仍带上，以便排队不丢上下文。
46. As a 当前 Session 的用户，我希望 Rewind / 编辑重发时网页元素已在历史 User Message 文本里，而不依赖草稿 store 再注入一遍，以便历史自包含。

### 浏览器控制设置

47. As a 桌面用户，我希望设置里有「浏览器控制」项，归在基础设置分组，以便找到内置浏览相关选项。
48. As a 桌面用户，我希望看到「忽略证书校验」开关及其风险说明：仅影响内置浏览器、修改后需重启生效，以便在内网自签证书场景下仍能打开页。
49. As a 桌面用户，我希望「清除缓存」只清 HTTP 缓存、Cache Storage 和 Service Worker，保留 Cookie 与本地站点数据，以便排障时不必重新登录。
50. As a 桌面用户，我希望「清除全部」会删除 Cookie、站点数据和缓存，并在执行前二次确认，确认文案标明不可撤销，以便误触有门槛。
51. As a 桌面用户，清除完成后我希望已打开的浏览器页重新加载或提示已清资料，以便立刻看到效果。
52. As a 桌面用户，我希望「开启内置浏览器控制」开关可以保存，但首版不决定能否打开侧边栏浏览器，以便后续智能体网页工具有配置位，同时日常浏览不被隐藏开关挡住。
53. As a 桌面用户，我希望该开关的说明写的是「允许后续会话通过内置浏览器操作网页」，而不是「Browser Use 官方插件」，以便名称与实现一致。
54. As a 系统维护者，我希望浏览器控制写入应用配置（与主题、通知同级），缺省为关闭证书忽略、关闭智能体浏览控制，以便旧配置文件仍能反序列化。

### 安全、失败与焦点

55. As a 桌面用户，我希望内置浏览器不能把页面脚本调进应用 IPC，以便恶意站点不能驱动 CodeMUX。
56. As a 桌面用户，我希望导航失败（DNS、证书被拒、被策略拦截）时在浏览器面板内看到错误而不是整应用崩溃。
57. As a 桌面用户，当检查模式关闭时，我希望页面内的点击、输入、滚动按普通网页工作，以便能正常使用表单和搜索框。
58. As a 桌面用户，我希望在地址栏敲字时快捷键优先给地址栏，而不是误发给聊天 Composer，以便能 Cmd/Ctrl+A 全选 URL。
59. As a 桌面用户，我希望未聚焦网页时，应用原有 Composer 快捷键仍可用，以便聊天不被内置浏览抢走。

### 可观测性（维护者）

60. As a 系统维护者，我希望创建、销毁、导航、清资料的失败打到应用日志并带上浏览器页身份，以便排障。
61. As a 系统维护者，我希望首版不把内置浏览接到 Mobile Companion，以免移动端出现半残 WebView。

## Implementation Decisions

### 分期

本规格只覆盖 **用户可见浏览 + 元素捕获 + 浏览器控制设置**。智能体 `browser_*` 自动化工具、ARIA snapshot、受信任点击/输入、设备尺寸预设、`window.open` 转新页、元素区域截图、键盘隔离打磨、Mobile Companion 内嵌浏览，全部放到后续规格。

首版实施前允许一次短 Spike：在侧边面板内容区创建子 WebView、加载 https 页、随面板改尺寸、hide/show 不丢页。Spike 不改变本规格的对外行为，失败则停止实现并回报宿主约束。

### 主测试接缝：Browser Host

前端、设置、元素注入都只通过一个 **Browser Host** 契约说话。这是本功能的最高接缝，对齐现有终端会话 API：UI 测假 Host，Rust 测真 Host 的命令语义（创建、导航守卫、清资料、事件投影）。不要让 React 组件直接操作 WebView 句柄。

Host 命令（语义，不是最终函数名）：

- 创建浏览器页 → 返回稳定 `browserId`
- 销毁
- 导航（仅允许 http/https）
- 后退 / 前进 / 刷新
- 设置内容区边界（逻辑像素或物理像素由实现统一，调用方只传侧边面板内容区矩形）
- 显示 / 隐藏（停放：隐藏时保留 DOM、Cookie、滚动）
- 在页内执行脚本（仅供元素检查注入与结果回收；脚本源由应用提供，不执行页面提交的任意字符串作为应用逻辑）
- 按范围清除浏览资料：`cache`（保留 Cookie/站点数据）或 `all`

Host 事件（推到前端 store）：

- URL、标题、favicon、是否加载中、能否后退/前进、最后一次导航错误

所有浏览器页共用一份应用本地 **浏览器资料目录**，与主界面 WebView 的应用资料隔离，以免站点 Cookie 与应用自身存储混用。

子 WebView **不得**列入可调用应用命令的 capability 窗口/视图集合；只有主界面可以 invoke Host。

### 面板模型

侧边面板增加一种 `browser` 标签。一个 Session 作用域最多一个浏览器面板；面板内部的多页由独立的浏览器页表维护（`browserId` → 元数据）。侧边面板标签只存 `browserId` 列表或「该面板存在」的标记，不把每个 URL 提升为侧边面板顶层标签。

打开浏览器不要求 `projectPath`。空状态「浏览器」与「+」菜单在无项目时仍可用（与审查/终端不同，后两者继续要求项目）。

关闭最后一个浏览器页的行为：**销毁浏览器面板并回到侧边面板空状态**（若该作用域没有其他标签）。不要留下只有工具栏、没有页的空面板。

新建页默认 URL 为空（空白页）。不内置百度或其他搜索引擎首页。

### 导航守卫

仅 `http` 与 `https`。用户输入缺省协议时补 `https://`。其余 scheme 拒绝并写入该页的 `lastError`。主进程/Host 层再拦一遍，防止页内重定向绕过地址栏。

### 元素检查

检查模式由前端开关驱动：Host 向当前页注入应用提供的选取脚本，轮询或回调回收结果。捕获字段至少包括：标签名、可见文本摘要、选择器（尽力）、包围盒、计算后的 color 与 font。不在首版要求 React source 或完整 computed style 表。

连续多选：捕获一次后保持检查模式，直到用户再点检查按钮或按 Escape。

页面卸载/导航时必须拆除选取脚本并结束检查模式。

### 网页元素与 User Message

网页元素 **不是** 新的 Attachment 类型，不进入 Attachment Enrichment（尊重现有「首版 Attachment 仅为 image」的决策）。它们是 Session 作用域的 Composer 引用：发送时格式化为 User Message 文本块，再走现有 `AgentInputPayload.text`。

文本块形状（发送契约）：

```xml
<browser-element url="https://example.com/path">
  <tag>div</tag>
  <text>可见文本摘要</text>
  <selector>尽力得到的选择器</selector>
</browser-element>
```

多元素按捕获顺序拼接。可见文本截断到固定上限，避免把整页 HTML 塞进一轮。不发送完整 `outerHTML` 作为默认载荷（体积与噪声太大）；若后续规格要给智能体更完整 DOM，另开。

历史 User Message 保存的是已经合并进正文的文本；刷新后不依赖草稿引用 store 还原。

### 配置

应用配置增加浏览器控制段，缺省值必须让旧 `config.json` 仍能反序列化：

- `enabled`：智能体网页操作预留，默认 `false`，首版不门控侧边栏入口
- `ignore_certificate_errors`：默认 `false`；改为 `true` 后须重启才作用于新建的浏览器页
- 清资料走 Host 命令，不写进配置文件

设置 UI 文案使用「内置浏览器」，不出现 Browser Use 品牌名。

忽略证书仅作用于内置浏览器资料下的子 WebView，不影响主界面加载应用自身。

### 布局与停放

浏览器面板的 React 层只画标签栏、工具栏、以及一块用于测量的内容占位。Host 把子 WebView 对齐到该占位的屏幕坐标。面板 resize、窗口 resize、展开/折叠、切换标签都必须更新边界或 hide。非激活的浏览器页 hide；激活页 show。不要用 1×1 停车作为首版策略——Tauri hide/show 即可；若 Spike 证明 hide 后无法恢复绘制，再单独立项，不在本规格扩散 Paseo 的 compositor 细节。

### 明确不采用的路径

- iframe 嵌入第三方站点
- 独立无边框 Browser 窗口（脱离侧边面板）
- 把每个 URL 做成侧边面板顶层标签
- 复用主界面 WebView 导航到外站
- 引入 Python/Node 的 browser-use 包作为运行时依赖
- 为智能体单独再开一套不共享资料的隐身浏览器（首版与用户共用资料；智能体工具本身不在本规格）

## Testing Decisions

好的测试只断言用户可观察的行为与 Host 契约，不断言 WebView 控件内部类名、注入脚本的具体轮询间隔、或 Rust 里 HashMap 的键格式。

### 主接缝：Browser Host

- **前端**：所有面板、工具栏、检查模式测试都注入假 Host。断言创建/导航/后退/边界/显示隐藏/清资料的调用参数，以及 Host 事件如何投影到页标题、地址栏禁用态、错误提示。
- **Rust**：命令层测试导航守卫（拒绝非 http(s)）、缺省 `https` 补全、capability 隔离（子视图不能 invoke 应用命令——至少以「创建时使用的标签/权限」配置断言）、清资料两种范围的参数分流。能在无 GUI 的单测里测的就不要开窗口。

Prior art：终端 API 的前端封装测试；侧边面板 store 测试（打开/复用/关闭标签、作用域切换）。

### 次接缝：网页元素格式化（纯函数）

输入捕获结果 → 输出 Composer 引用模型 + 发送用文本块。覆盖：截断、缺选择器、多元素顺序、空文本时仍保留 tag、URL 原样进入块。不测真实 DOM。

Prior art：Composer 路径引用的格式化函数测试。

### 配置与设置

旧配置缺浏览器字段时反序列化成功且缺省正确。忽略证书、预留 `enabled` 的读写经现有设置 store 同类测试。清除全部必须先确认；测试确认框取消时 Host 不被调用。

Prior art：应用配置缺省与旧 JSON 反序列化测试；设置页开关组件测试。

### 侧边面板集成

- 无项目也可打开浏览器；审查/终端仍要项目
- 同一作用域打开浏览器只产生一个 `browser` 顶层标签
- 关闭浏览器面板会销毁其下所有 `browserId`（经假 Host 断言 destroy 被调用）
- 切换 Session 作用域时隐藏旧页、不再把元素引用带到另一 Session

Prior art：侧边面板 store 的 scope / 打开复用测试。

### 不在首版测

- 真实百度首页渲染、真实证书错误对话框像素
- 智能体是否读懂 `<browser-element>`
- hide 之后 GPU 合成器是否仍能截图（无截图需求）
- Mobile Companion

## Out of Scope

- 智能体 `browser_*` 工具、ARIA snapshot、CDP 受信任输入、Broker 多 Host 路由
- 「辅助对话」侧边栏标签
- 设备尺寸预设、响应式视口切换
- `window.open` / `target=_blank` 转新浏览器页（首版按 WebView 默认行为；不保证新标签）
- 元素区域截图作为图片 Attachment
- 把网页元素做成新的 `AgentInputAttachment` 类型或 Enrichment Processor
- 书签、历史记录库、下载管理、扩展、广告拦截
- Mobile Companion 内嵌浏览
- Linux/macOS 与 Windows 行为差异的专项适配超出「同一 Host 契约」的部分：契约必须跨平台，但本规格不承诺三端像素级一致
- 修改现有「Markdown 链接用系统浏览器打开」的默认行为（聊天里的 http 链接仍走系统浏览器，除非用户主动在内置浏览器打开）

## Further Notes

- 领域用语建议写入 glossary：**内置浏览器**（用户在侧边面板里看的网页运行时，不是系统浏览器，也不是 Mobile Companion）、**浏览器面板**（侧边面板的一种标签）、**浏览器页**（面板内的一个 `browserId`）、**浏览器资料**（共享的 Cookie/缓存目录）、**网页元素**（检查模式捕获、写入 User Message 的引用）、**元素检查模式**、**Browser Host**（前端与原生 WebView 之间的唯一接缝）。避免：iframe、webview 窗口、Browser Use、tab（未说明是侧边面板标签还是浏览器页时）。
- Paseo 可借鉴：resident 页（创建后 hide 而不是反复 new）、元素选取与 Composer 引用分离、共享 profile、智能体工具默认关闭。不可照搬：Electron `<webview>`、1×1 parking geometry、daemon WebSocket broker、22 个 `browser_*` MCP 命令。
- 图中设置页的「开启内置浏览器控制」对应后续规格的智能体网页工具开关；若首版 UI 要完整复现该页，开关可展示但必须写清「不影响侧边栏打开浏览器」。
- 实施顺序建议：Host Spike → 侧边面板入口与空白页导航 → 多浏览器页与停放 → 元素检查与 Composer 文本块 → 设置页清资料与证书开关。
