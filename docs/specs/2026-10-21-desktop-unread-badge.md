# 桌面未读角标：任务栏与托盘提示点

**Status:** ready-for-agent

## Problem Statement

用户把 CodeMUX 最小化、关到托盘，或者切去别的窗口干活时，一个 Session 的 Turn Outcome 到达了（完成、失败、被中断），用户却完全不知道。现在只有两条提醒途径：

- 系统通知 —— 一闪而过，专注别的事情时很容易错过，而且用户可能主动关掉了它；
- 侧栏会话行上的状态点 —— 前提是窗口正开着、而且用户正看着侧栏。

结果是用户每隔一阵就要主动切回来确认「跑完了没有」。定时任务和 Mobile Companion 发起的 Turn 尤其明显：它们本来就是在用户不看的时候跑的，跑完了却没有任何常驻的视觉痕迹。

任务栏和托盘是这类「后台任务有结果了」最自然的落点：不需要打断用户，扫一眼就知道有几个 Session 还没看。

## Solution

在桌面壳上做一层常驻的未读提示：

- **Windows 任务栏**：应用按钮右下角出现一个纯红圆点（Shell 的 taskbar overlay，位置由系统固定，与 Windows 更新盾牌、Outlook 同步状态同一机制）。
- **托盘图标**：图标右上角合成同一个红点。
- **macOS / Linux**：走系统应用级角标（Dock / LauncherEntry）。

红点表示「有几个 Session 自上次查看后产生了新的 Turn Outcome 且用户还没打开过」。用户点开那个 Session，红点计数减一；全部看完，红点消失。

角标是**被动、安静**的：不闪任务栏、不抢焦点、不额外弹通知。它只回答一个问题——「有没有我还没看的对话」。

## User Stories

1. 作为桌面用户，我希望在 CodeMUX 被最小化或关到托盘时，任务栏图标上出现提示点，这样我不用反复切回窗口确认 agent 跑完没有。
2. 作为桌面用户，我希望托盘图标右上角也出现同一个提示点，这样即使任务栏被其他窗口占满，我在通知区域也能看到。
3. 作为同时开多个 Session 的用户，我希望提示点覆盖所有会话的未读结果，而不只是当前打开的那一条。
4. 作为用户，我希望点开某个未读 Session 后提示点计数相应减少，这样我知道还剩几个没看。
5. 作为用户，我希望所有未读都看完后提示点彻底消失，而不是留一个常驻装饰。
6. 作为用户，我希望「跑完了」和「跑失败了」都会产生提示点，这样失败不会被静默吞掉。
7. 作为用户，我希望「跑完了但我正开着这个 Session 在看」时不要给我打未读，这样我不会看到一个自己明明正在看的会话被标成未读。
8. 作为用户，我希望「我正开着这个 Session 但窗口在后台」时仍然得到提示点，因为那一刻我确实没在看，这正是最需要提醒的场景。
9. 作为用户，当我从别的窗口切回 CodeMUX、并且仍然停在那个刚跑完的 Session 上时，我希望提示点自动消掉，而不是逼我先点走再点回来。
10. 作为用户，如果我离开期间切去看过别的 Session，我希望那个会话的未读**保留**，作为回来处理的提醒。
11. 作为用户，我希望手动「标记为未读」的会话也计入提示点，这样我可以用同一套视觉管理待回看的对话。
12. 作为用户，我希望手动标记的未读不会因为我碰巧切回窗口就被自动清除，只有我真正打开它才清除。
13. 作为用户，我希望删除或归档一个未读 Session 后提示点立刻减少，不要留下一个点不掉的幽灵角标。
14. 作为使用定时任务的用户，我希望后台到点跑完的 Task Run 产生提示点，这样我不用守着自动化页面。
15. 作为使用 Mobile Companion 的用户，我希望手机端发起、桌面端执行的 Turn 完成后桌面壳有提示点，这样我回到电脑前就知道有结果了。
16. 作为用户，我希望提示点不因为我关掉了系统通知开关而消失，因为角标是被动的、不打扰，和弹窗通知是两回事。
17. 作为用户，我希望提示点不闪任务栏、不抢焦点，因为我在专注做别的事。
18. 作为使用 Windows 10 的用户，我希望红点位置正常居中在角标槽位里，而不是偏到角落或被裁掉一块。
19. 作为使用 Windows 11 的用户，我希望红点在系统已放到图标角上的 overlay 里再居中，不要出现二次偏移。
20. 作为使用高 DPI 屏幕的用户，我希望红点边缘是抗锯齿的圆，而不是糊成一团的锯齿方块。
21. 作为使用深色任务栏的用户，我希望红点在浅色和深色任务栏上都清晰可辨。
22. 作为使用 macOS 的用户，我希望 Dock 图标上显示未读数角标。
23. 作为使用 Linux 桌面的用户，我希望启动器角标和托盘红点都能工作。
24. 作为浏览器形态用户（daemon 直接服务的网页），我不应该看到任何报错或降级提示，因为那里根本没有任务栏。
25. 作为用户，我希望 CodeMUX 启动时如果已经有未读，提示点立刻出现，而不是等到下一个 Turn 结束才亮。
26. 作为用户，我希望提示点的更新是即时的，在 CodeMUX 里发起、最小化等它跑完的这条主路径上不要有明显延迟。
27. 作为用户，我希望提示点在应用退出后不留残余。
28. 作为维护者，我希望角标计数与侧栏状态点使用**同一份**未读真值，不要出现「有角标没蓝点」或反过来的情况。
29. 作为维护者，我希望红点图像是纯函数算出来的，能在 Node 里单测像素与平台分叉，而不必起 Electron。
30. 作为维护者，我希望渲染层与壳之间的新通道是一个幂等的、带载荷校验的单向通知，而不是一个新的状态同步机制。
31. 作为维护者，我希望「等待确认」（权限审批 / AI 提问）不被混进这个角标，保持它只表达「有对话没看」。
32. 作为维护者，我希望这次改动不碰 Daemon，因为未读真值本来就在渲染层内存里，把它搬进 Daemon 是另一个量级的工程。

## Implementation Decisions

### 数据来源与口径

- **未读真值不迁移。** 继续使用渲染层 Session 状态里的 `unreadSessions` 集合。Daemon 不感知「未读」这个概念，本规格不新增 Daemon 表、事件或协议。
- **角标计数是纯函数选择器**，输入是会话列表与未读集合，输出一个非负整数。口径：
  - 只数**仍存在于当前会话列表**里的 Session（已删除的不算）；
  - 已归档的 Session 不算（与侧栏一致：归档区不参与常驻提醒）；
  - 与侧栏状态点同源，保证「角标数 = 侧栏能看到的未读蓝点数」。
- **不混入其他注意力状态。** Interactive Request（权限审批、AI 提问）与 Work Task 的「等你处理」计数都不进这个角标；它们各有自己的应用内徽章。理由：角标要能对上侧栏蓝点，混入别的信号就会出现「有角标、找不到落点」的幽灵提醒。
- **角标不受系统通知开关控制。** 系统通知会打断用户，角标不会，两者独立。若日后要联动，在渲染层同步前加一道 gate 即可。

### 未读的写入与清除

- **焦点感知的标记规则。** 现有实现里「标记未读」对当前活跃 Session 直接跳过。改为：只有当**应用处于前台焦点**且该 Session 是活跃 Session 时才跳过。即「开着这个会话、但窗口在后台」仍会标未读。
- **后台补记集合。** 因「活跃但无焦点」被标上的未读，记入一个独立的集合，用于回焦自动清除。它不是第二个未读真值，只是标记来源的元数据。
- **回焦自动清除。** 窗口重新获得焦点时，若当前活跃 Session 属于后台补记集合，自动清除它的未读。手动「标记为未读」的 Session 不进这个集合，因此不会被回焦误清。
- **删除与归档要 prune。** 删除或归档一个 Session 时同步从未读集合中移除它，避免幽灵计数。
- **前台判定**收敛为一个可注入的小工具：有 `document` 时读 `document.hasFocus()`；没有 `document`（Node 测试、SSR）时视为前台，以保持既有 store 行为与测试不变。

### 渲染层 → 壳 的通道

- 新增一条壳 IPC 调用通道，语义是**单向、幂等、可重复**的计数同步：`syncUnreadBadgeCount(count)`，载荷为非负整数。
- 载荷校验（必须是整数且 ≥ 0）下沉到壳侧的角标纯模块里，作为可单测的解析函数；IPC 注册处只做转发，非法载荷直接拒绝。
- 渲染层用一个全局 hook 订阅计数变化并同步壳；**计数不变不发包**（hook 内记住上一次发出的值）。
- 壳桥缺失（浏览器形态）时 hook 静默降级，不报错、不弹 toast。
- 该能力归 `shell` 一侧，进能力清单（与托盘同属壳独占能力面），浏览器/移动形态据此隐藏或跳过。

### 壳侧渲染

- 新增一个**不 import Electron** 的角标模块，负责纯计算：
  - 4× 超采样的预乘 alpha BGRA 圆点渲染（抗锯齿边缘不产生白边/脏边）；
  - 预乘 alpha 合成（把红点贴进托盘图标位图）；
  - Windows 版本分叉：OS build ≥ 22000（Windows 11）在画布内居中；更早（Windows 10）在画布内右下锚定，补偿旧任务栏 overlay 的落点差异；
  - 计数 → 文案标签的解析，0 表示「移除角标」；
  - 徽章图按标签缓存在内存里，更新是事件级的查表 + 一次 Shell 调用。
- **Windows**：对每个窗口调 `setOverlayIcon`。计数为 0 时传 `null` 移除。已销毁的窗口跳过。无障碍描述携带具体数量（中文文案，与壳侧现有托盘菜单、控制提示条一致）。overlay 不渲染数字，所以生产上只画红点。
- **托盘（Windows / Linux）**：把红点合成到图标右上角，同时提供原生 1x（16px）与 2x（32px）两个 representation，避免把硬边图交给 Shell 盲缩；计数归零时恢复原始图标。没有托盘实例时是 no-op。
- **macOS**：走应用级 `setBadgeCount`，不做托盘合成（macOS 托盘由 Dock 角标承担，壳侧本就不建托盘）。
- **Linux**：应用级角标 + 托盘红点双保险（原生 GNOME 没有 badge API 时靠托盘兜底）。
- **启动补齐**：主窗口首次 `ready-to-show` 时，壳把当前角标值再应用一次，覆盖「渲染层先同步、壳还没就绪」的时序。
- **多窗口聚合**：所有窗口显示同一个全局计数；控制提示条窗口是 skipTaskbar 的，对它设置 overlay 无副作用，不单独排除。

### 明确不做

- 不闪任务栏、不请求用户注意（`flashFrame` / `requestUserAttention`）——与「安静提醒」的产品意图冲突。
- 不在角标上渲染数字——16px 显示尺寸下不可读。
- 不改系统通知的既有行为。

## Testing Decisions

**好测试的判据：** 只断言外部可观察的行为——给定输入产出什么计数、发了什么载荷、调用了几次壳方法、像素数组的关键位置是什么颜色。不断言内部实现细节（不测私有字段、不测中间变量、不测调用顺序中无关的部分）。

**测试缝：三条，全部是既有缝，不新增跨进程缝。**

1. **会话状态的选择器与动作。**
   - 覆盖：计数口径（只数在列表里且未归档的）、删除/归档时 prune、焦点感知的未读标记、回焦自动清除只清后台补记。
   - 先例：会话状态现有的单测（既有「活跃会话标记未读被跳过」「非活跃会话标记未读生效」两条用例保持原语义，靠「无 `document` 视为前台」继续通过）。

2. **全局未读角标 hook。**
   - 覆盖：计数变化才同步壳、计数不变不发包、回焦清除只作用于后台补记集合、壳桥缺失时静默降级。
   - 先例：系统通知 hook 的测试（用替身壳门面 + 受控 store 状态驱动，断言对外调用）。

3. **壳侧角标纯模块。**
   - 覆盖：像素数组的尺寸与关键像素颜色、预乘 alpha 合成的边界裁剪、Windows 10 与 Windows 11 的圆心分叉、计数为 0 时传 `null`、跳过已销毁窗口、多窗口都收到同一角标、IPC 载荷校验接受/拒绝、徽章图按标签缓存。
   - 先例：控制提示条窗口的纯函数测试、桌面 UI 事件解析测试——都是「纯模块 + 假窗口对象」的写法，无需起 Electron。

**不单独为壳的 IPC 注册开测试缝。** 那一层只有一行转发，载荷校验已经在缝 3 里覆盖；再开一条缝测的是转发本身，价值低于维护成本。

**不新增跨进程测试缝。** 渲染层与壳之间没有现成的可注入边界，硬造一个会比分别测两侧更脆。

**手工验收（Windows，写进 PR 描述）：** 完成任务 → 任务栏右下角出现红点、托盘右上角出现红点；打开会话 → 双双消失；同时有 2 个未读 → 打开其中一个 → 仍然亮着；全部读完 → 消失；关掉系统通知开关 → 红点仍然工作；窗口最小化 → 红点仍可见。

## Out of Scope

- **数字角标**（1–9 / 9+）。红点不带数量。
- **任务栏闪烁 / 请求用户注意 / 缩略图工具栏 / 跳转列表**。
- **把未读状态持久化到 Daemon**、跨设备同步、跨桌面实例同步。
- **Interactive Request 与 Work Task 注意力计入角标**（它们已有各自的应用内徽章与通知）。
- **角标与系统通知开关联动**。
- **Mobile Companion**：浏览器形态没有任务栏概念，不适用。
- **macOS / Linux 实机验收**：只保证代码路径与单元测试，实机效果标注为未实测。
- **overlay 的交互**（点击、悬停）：Windows 不提供相应 API，点击 overlay 区域等同于点击任务栏按钮。
- **自定义角标颜色 / 图标主题**。

## Further Notes

- **参考实现**：ZCode 的桌面端做过同一件事，链路是「渲染层统计未读 → IPC 同步计数 → 主进程按平台分叉」。它的两条教训被本规格直接吸收：(1) 计数只读侧栏实际渲染的那份权威数据，不要从只加载活跃工作区的缓存里数，否则会出现背景会话蓝点亮着、角标却是 0；(2) 徽章图必须按目标尺寸超采样生成并同时给 1x/2x 表示，直接把 32px 硬边图交给 Shell 缩放会糊。本规格不复用它的代码，只复用结论。
- **已知延迟边界**：窗口被遮挡/失焦时 Chromium 的 `backgroundThrottling` 默认生效，`agentStore` 里那条 1 秒轮询（定时任务、Mobile Companion 发起的 Turn 的唯一完成通道）最坏会被压到分钟级，角标可能延迟。这与现有「跑完了」系统通知是**同一个**限制，不是本次新引入的。在 CodeMUX 内发起、最小化等它跑完的主路径走 WebSocket 实时流，不受影响。
- **窗口关到托盘时**，任务栏 overlay 不可见（窗口没有任务栏按钮），此时提示完全由托盘红点承担——这正是托盘角标必须做的原因。
- **Windows 10 / 11 圆心分叉**是本规格里唯一「必须靠实机确认」的实现细节。若日后发现某一代系统更新改变了 overlay 落点，只需调整分叉阈值与圆心，其余链路不变。
- 本规格只产出 spec；实现拆票见后续 `docs/tickets/desktop-unread-badge/`。
